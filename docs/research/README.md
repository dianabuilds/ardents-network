# Research workspace

Research exists to make a named product or architecture decision. It is not a
holding area for interesting links and is not a way to smuggle an implementation
choice into the repository.

## Workflow

1. Select or add a decision-relevant question in
   [questions.md](questions.md).
2. Create `docs/research/records/<question-id>-<slug>.md` from
   [template.md](template.md).
3. Define hypotheses, comparison criteria, adversary, and falsification before
   collecting evidence.
4. Prefer primary sources and reproducible measurements.
5. Place disposable code in `experiments/<question-id>-<slug>/`.
6. Write the result even when the hypothesis fails.
7. Mark the recommendation, confidence, unresolved risks, and exact product
   decision it unlocks.
8. Create an ADR only if an actual hard-to-reverse decision is accepted.

## Evidence labels

- **Sourced fact** — supported by a cited specification, paper, official
  documentation, code, or advisory.
- **Measurement** — generated by a reproducible experiment with environment and
  artifacts recorded.
- **Assumption** — currently unverified and explicitly exposed.
- **Inference** — conclusion derived from stated facts or measurements.
- **Recommendation** — proposed decision, not truth about the world.

## Research states

- `open` — question and decision criteria exist;
- `active` — evidence collection or experiment is in progress;
- `review` — recommendation is ready for adversarial review;
- `decided` — a decision was accepted and, when appropriate, captured in an ADR;
- `blocked` — a named missing input prevents useful progress;
- `rejected` — the question or approach no longer serves the product direction.

## Quality bar

A record is decision-ready only when it includes competing options, threat-model
fit, operational and governance dependencies, failure cases, maintenance health,
licensing, and an explicit “do not choose any yet” result when evidence is
insufficient.

See [reference systems](reference-systems.md) for the starting landscape. Those
systems are sources of patterns and evidence, not preselected dependencies.
