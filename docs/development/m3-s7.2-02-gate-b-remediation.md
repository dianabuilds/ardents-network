## Disposition of the partial implementation

### Platform lock files: retain the responsibility, rewrite the evidence flow

The build tags, private names, and one-file-per-platform responsibility may be
retained. The current implementation is not acceptable.

Both platforms must:

1. open the installer-created lock without create, replacement, unlink, or
   retry;
2. acquire the non-blocking OS lock before treating any identity observation as
   authoritative;
3. prove through the held handle that the object is a direct, regular, empty,
   single-link file and that the current path names that same object;
4. classify only the platform's actual lock-contention result as `busy`;
5. classify permission, unsupported-operation, identity, and other syscall
   failures as invalid lock evidence; and
6. observe and join every unlock and close error, including failed-acquire
   cleanup.

On non-Windows, `file.Name()` is not identity evidence. Compare held-handle
`fstat` with non-following path evidence after `Flock`, including device, inode,
type, and link count. Only `EWOULDBLOCK`/`EAGAIN` proves contention.

On Windows, `GetFileAttributes(path)` plus `file.Name()` is not identity
evidence. Use handle information and a non-reparse path handle to prove the
same volume/file identity and `NumberOfLinks == 1`. Only
`ERROR_LOCK_VIOLATION` proves contention; `ERROR_ACCESS_DENIED` does not.

### `recovery_inventory.go`: retain only the named responsibility

Discard the current fact model and implementation. Local patching is rejected:
it cannot supply enough immutable physical evidence for a pure planner.

The replacement performs one bounded read-only pass after lock ownership and
records, without classifying a recovery row:

- exact root children and their direct physical kind;
- exact marker and current raw bytes plus identity facts;
- every canonical generation directory and exact artifact/manifest raw facts;
- every staging child and exact candidate facts;
- every transaction directory, including its canonical name and physical
  children;
- every journal directory child as a raw named entry, including gaps, extras,
  aliases, and non-regular objects; and
- every candidate current-temp name, identity, and bounded raw bytes.

The interrupted transaction is discovered by enumerating `transactions/`; it
is not inferred from `current.Transaction`. The inventory must expose enough
facts for the planner to reject a second transaction, reused generation,
missing journal directory, noncanonical numeric name, unknown child, malformed
marker, and link/reparse evidence without another filesystem read.

Inventory does not decode journal entries, verify their chain, classify
R00-R14, construct a Result, or execute cleanup. Those responsibilities remain
in `recovery_journal.go`, `recovery_plan.go`, `recovery.go`, and `cleanup.go`.

Every file read is size-bounded before allocation and revalidates the opened
handle. `os.ReadFile` is forbidden in the recovery inventory. Numeric names are
canonical only when parsing and formatting round-trip byte-for-byte. A current
temporary name is exactly `.current.` plus 16 lowercase hexadecimal characters
plus `.tmp`.

## Second-pass controller remediation — 2026-08-21

The next Gate B pass produced useful R00-R14 code but was rejected by an
independent Standards+Spec review. It had five failing test groups, three
cleanup-overrun rows still skipped, destructive permanent-lock handling, a
package-global journal fact map, incomplete physical binding, hidden release
errors, and no real Apply interruption driver. Its report also undercounted the
worktree as 15 files when `git status` showed 17. No commit is authorized.

The controller preserves the frozen eight Gate A files, the typed operation
vocabulary, and the broad inventory/journal/planner separation. The following
amendments replace conflicting earlier remediation text and are executable in a
fresh M3 context against the existing uncommitted worktree.

### Permanent lock amendment

The lock is installer/portable-bootstrap owned. `Apply` and `Recover` never
create, repair, replace, truncate, or unlink it. Remove
`bootstrapPermanentLock` from both public operations and from production.
Every V0/root test fixture, including the command fixture, creates the exact
direct regular empty single-link lock before calling the Module. Missing lock is
then an observable `transaction-invalid` mutation.

Non-Windows opens the lock once, without create and without following links,
obtains the non-blocking OS lock, validates the held handle, then compares that
identity with a non-following path observation. Windows calls `CreateFile`
exactly once with `OPEN_EXISTING`, `FILE_FLAG_OPEN_REPARSE_POINT`, and zero share
mode, then calls non-blocking `LockFileEx` and validates file attributes, size
zero, and `NumberOfLinks == 1` through that held handle. Because zero share mode
is the platform exclusion primitive, `ERROR_SHARING_VIOLATION` during the one
open and `ERROR_LOCK_VIOLATION` during `LockFileEx` are the only Windows busy
classifications. ACL/access, missing, reparse, directory, non-empty, linked, or
other failures are invalid/unsupported evidence, never busy.

Release joins unlock and close errors and never removes the path. `Apply` and
`Recover` must observe every release error and map it to the accepted bounded
failure without overwriting the last coherent state. No deferred `_ = release`
or ignored handle close remains.

### Immutable inventory and physical binding amendment

`journalFacts` and every other package-global mutable fact are forbidden.
Journal raw facts belong to the corresponding `transactionFacts` inside one
`inventoryResult`; concurrent/repeated roots cannot share state. Inventory
rejects every unknown root file **or directory**, empty/unknown generation,
missing selected generation, second transaction, noncanonical name, alias, and
missing or extra journal child. A bounded handle read observes and joins close
errors; it never uses `os.ReadFile`.

If keeping these invariants cohesive would leave `recovery_inventory.go` with
multiple independent responsibilities, move only low-level bounded handle read
and identity extraction to `recovery_files.go`. Journal decoding and state-name
mapping remain solely in `recovery_journal.go`; semantic physical selection
validation remains solely in the pure planner. The planner consumes only its
arguments, performs no filesystem read, uses no package-global state, and does
not re-encode a current record when exact observed bytes already exist.

The journal validator binds the canonical entry artifact/manifest commitments
to the exact candidate physical facts admitted by the inventory, not merely to
non-zero digests or a self-consistent attacker-selected chain.

### Tests and fault seams

The eight Gate A hashes remain unchanged. Non-growing fixture/expectation edits
are permitted in existing `journal_test.go`, `transaction_test.go`, and
`cmd/ardents-release/main_test.go` only to add the permanent bootstrap lock,
expect the new `transaction-invalid` Recover outcome, and assert that the lock
remains present/empty. They may not weaken a mutation or recovery row.

Add focused Gate B tests outside the frozen files for:

1. every cleanup operation failure plus one real five-second overrun proving no
   later operation starts;
2. the private per-invocation Apply checkpoint control at every accepted
   before/after publication boundary;
3. two concurrent roots and repeated Recover calls proving no fact leakage or
   race; and
4. Windows busy, missing, non-empty, directory, and held-handle identity rows.

The Apply checkpoint control is private and per invocation: public `Apply`
calls an unexported implementation with nil control; package tests may pass one
bounded control value. It is not package-global, context-carried, or exported.
