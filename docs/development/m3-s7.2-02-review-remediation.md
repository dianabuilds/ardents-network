# S7.2-02 controller review and narrow remediation

Status: **remediation implemented; awaits controller verification and Product
Owner acceptance.** This record does not accept S7.2-02 or close C1.

## Review disposition

The controller reviewed `840266e` against the accepted S7.2-02 contract and
`m3-s7.2-02-v2-brief.md`. The review found two P1 deviations:

1. Windows lock acquisition checked the held object's shape but did not prove
   that its handle still named `.ardents-update-transaction-lock`.
2. R10/R11 restored the predecessor `current` record but retained the custody
   notice selected from the entry-time successor manifest.

The remediation is deliberately limited to those contract failures, a public
R10 regression test, a Windows-only final-path normalization test, and this
required file-cohesion evidence. It changes no exported declaration, record
format, dependency, command, or S7.2 outcome table.

## Remediation evidence

`lock_windows.go` now obtains the normalized DOS final path from the held,
non-blockingly locked handle with `GetFinalPathNameByHandleW`, normalizes only
the documented extended DOS/UNC forms, and fails closed unless it matches the
admitted lock path case-insensitively. The fixed 512-UTF-16-unit bound is
stricter than the existing accepted 240-unit owned-path bound. It creates no
second lock handle and therefore preserves the zero-share invariant.

`recovery_plan.go` now gets custody for R10/R11 from the exact verified
rollback tuple before constructing a plan which restores that predecessor. The
public `Recover` test `TestRecoverR10UsesRestoredPredecessorCustody` constructs
different valid predecessor and successor notices and proves the returned
notice is the predecessor's. It was red before the remediation and green after
it. `lock_windows_test.go` executes the DOS/UNC normalization cases and
`TestRecoverRejectsLockPathAlias` on the current Windows host. The latter
creates a real directory junction to the admitted root and proves public
`Recover` rejects the resulting held-handle/final-path mismatch before any
inventory mutation. `TestRecoverBusyDoesNotMutate` separately exercises
successful held-lock acquisition through the public `Apply`/`Recover` boundary.
This is pathname-identity evidence, not a claim of native power-loss or disk
fault qualification.
