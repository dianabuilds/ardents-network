## Why the failed worktree is not a baseline

Do not salvage, amend, copy, or use the failed S7.2-02 worktree as a source of
production code. Start from the exact clean acceptance SHA supplied by Codex.
This is mandatory because independent review found all of the following:

- R08-R11 normalization was destructive without first proving the complete
  journal and predecessor reconstruction oracle;
- journal validation did not implement the complete canonical, contiguous,
  commitment-bound oracle and could admit or classify incomplete evidence;
- cleanup measured the five-second rule incorrectly and could start or hide an

- file responsibilities were violated: admission, generation, policy, storage,
  and cleanup concerns were combined in files whose names did not own them.

These are correctness and evidence failures, not merely line-count failures.

trusted by default.

## Unchanged acceptance criteria

All six accepted task criteria remain conjunctive:

1. One independent table-driven test injects every fixed interruption point
   and asserts exact active, rollback, staging, schema, and journal
   commitments.
2. `Recover` performs exactly one bounded pass and never infers commit from
   file presence, executable success, or the candidate summary.
3. A crash after atomic replacement but before the platform durability
   acknowledgement permits only a complete predecessor or complete successor;
   the journal decides which is committed.
4. Corrupt or contradictory state returns `transaction-invalid`, performs no
   network work, and preserves repair/export reachability.
5. Recovery removes only the R00/R03/R08-R11 allowlist in deterministic plan
   order. It obeys the accepted five-second continuation budget, observes
   every failure and overrun, and starts no later step after expiry.
6. V0 record bytes, commitments, public Result, and command JSON pass
   unchanged. Its physical bootstrap and committed-root oracle includes the
   permanent empty lock, which is not hashed into a record or Result.

## Frozen invalid corpus

Each mutation below returns `transaction-invalid`, preserves every byte, calls
no Adapter, and neither removes nor replaces the permanent lock:

- malformed, partial, gapped, duplicated, extra, or out-of-order entry;
- broken first predecessor or later predecessor commitment;
- decreasing observation, extended deadline, wrong generation, artifact
  commitment, or manifest commitment;
- missing selected predecessor or candidate;
- candidate simultaneously in staging and generations;
- successor current before activation without the exact rollback predecessor;
- predecessor current with `activated`, `self-testing`, or `committed` prefix;
- successor current with only a pre-`draining` prefix;
- missing permanent lock, reused generation, second transaction, or unknown
  root child;
- current temp with wrong name or bytes;
- symlink, junction, reparse point, or hard link in admitted evidence.

The test suite must also mutate every bounded journal field independently:
envelope magic, kind, version, flags, body length, state code, generation,
predecessor commitment, candidate digest, manifest commitment, Adapter result,
observation, monotonic elapsed value, effective deadline, trailing byte, and
non-canonical re-encoding. Equivalent mutations may share a table but may not
share the production validator as their expected oracle.

## Frozen cleanup and lock rules

The cleanup allowlist is exactly R00 empty transaction directories, R03 exact
unacknowledged staging, R09 exact current temp, and reversible candidate/current
placement in R08-R11. Unexpected objects are never removed.

The deterministic plan uses the row's left-to-right operation order. Within an
admitted tree, path operations are deepest-first lexical; each required parent
sync is the immediately following distinct step. The executor checks the fixed
continuation budget immediately before every remove, move, replace, and sync,
then observes time and error immediately after every step. No new operation
starts at or after expiry. An already-started non-cancellable kernel operation
may return late, but its overrun produces `cleanup-incomplete` and no later
operation starts.

The installer-created lock is opened exactly once without create or retry,
then non-blockingly OS-locked and identity-checked through the held handle. It
is never repaired, replaced, or unlinked. Busy recovery returns the frozen busy
Result without mutation. Missing, changed, linked, non-regular, non-empty,
unsupported, or erroneous lock evidence fails closed.

## Gate B — complete production implementation

Only after Codex verifies and explicitly preserves Gate A does Gate B continue
in that same isolated red-test worktree. Do not restart from the failed
implementation or regenerate the oracle.

Gate B may add the seven new production files and make only the minimal
`transaction.go`/`store.go` edits in the responsibility map. It may add
test-only private-seam cases needed for real Apply interruption and deterministic
cleanup faults, but it may not change an expected value merely to obtain green.

The private Apply interruption control is per invocation. It stops immediately
before or after each journal write-and-sync, generation publication, complete
current-temp publication, native current replacement, and successful
replacement durability acknowledgement. The sentinel bypasses normal failure
cleanup and normal Result construction, preserves the checkpoint bytes, and
releases only the process-owned OS-lock handle. It is not exported,
package-global, or context-carried.

Only cleanup/failure tests may call one private per-invocation recovery
operation wrapper carrying typed remove, move, replace, and sync operations.
It cannot replace locking, inventory, decoding, validation, classification,
clocks, deadlines, or Results. Public `Recover` always uses native operations.

Gate B is complete only when every R00-R14 row, every publication boundary,
the full invalid corpus, busy ownership, every cleanup step failure, one
cleanup overrun, V0 byte compatibility, and all existing tests are green. If
any accepted criterion cannot fit, return `scope-blocked` without a production
commit.
