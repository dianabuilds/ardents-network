# Proposed contract amendment — S7.2-08 repeated pressure and cleanup

Status: **S7.2-08a engineering contract accepted by Codex under the Product
Owner's standing Stage 7.2 delegation, but blocked on its implementation
predecessors; S7.2-08b and complete C10 remain contract-blocked.** This document
does not authorize MiniMax M3 until the applicable baseline and Gate A are
committed. S7.2-08 remains open until both parts are implemented, reviewed, and
accepted by the Product Owner.

## Why the current full task is NO-GO

The accepted S7.2-08 contract requires repeated update, rollback, restart, and
cleanup pressure without unbounded retained state. The maintained format does
not yet define how a second committed transaction on the same update root
retires the preceding immutable journal, assigns its transaction ordinal, or
distinguishes transaction ordinal from payload generation. S7.2-06 and
S7.2-07 also leave owner-specific schema and Contributor terminal-inventory
compaction to later accepted rules.

M3 must not solve those missing lifetime rules by deleting old evidence,
reusing a journal filename, resetting a generation, treating
`repair-required` as retryable, or moving foreign-owned state into
`internal/updatetransaction`. A fresh-root regression is useful development
evidence, but it cannot prove bounded repeated updates on one installed root.

The smallest faithful split is:

- **S7.2-08a:** a test-only, exact 100-invocation pressure regression over
  fresh roots and paired recovery calls; and
- **S7.2-08b:** the complete same-root C10 campaign, blocked until the
  retirement and owner-compaction decisions in this document are accepted.

## S7.2-08a — test-only bounded pressure regression

### A1 — scope and claim ceiling

08a changes tests only under `internal/updatetransaction`. It adds no
production code, public Interface or `Result` field, journal/schema/current
format, logger, daemon, telemetry, command, package, dependency, or
`package-map.md` row. It uses only already accepted private per-invocation
fault/clock seams and public `Apply`/`Recover` behavior.

08a proves that the already implemented transaction paths have deterministic
bounded physical inventories and release all test-owned runtime resources over
the frozen campaign below. It does **not** prove:

- repeated committed transactions on one update root;
- retirement or compaction of immutable journals, schema owner state, or
  Contributor terminal inventories;
- live Contributor process replacement or cleanup;
- native disk-full, inode-full, reboot, or hard-power behavior; or
- C10 completion. **Accepting 08a does not close S7.2-08 or C10.**

### A2 — exact 100-invocation oracle

The campaign has five blocks of the same exact 20-row sequence. Blocks are
numbered `00..04`, rows `01..20`, and roots are named only in the test temp
directory as `root-<block>-<row>`. `R` reuses the immediately preceding `I`
root and `Q` reuses the immediately preceding `F` root. Every other row starts
from a newly bootstrapped V0 root. No root is reused after `repair-required`.

| Row | Code | Fixed invocation | Expected `Outcome/State` |
|---:|---|---|---|
| 01 | S | V0 successful `Apply` on a fresh root | `committed/committed` |
| 02 | P | accepted Decision with candidate length `67,108,865`, rejected before root inspection | `resource-denied/release-accepted` |
| 03 | I | V0 `Apply` interrupted immediately after durable `staged` | injected interruption; coherent state `staged` |
| 04 | R | `Recover` the row-03 root | `recovered/staged` |
| 05 | B | forward local self-test failure and safe retained rollback | `rolled-back/rolled-back` |
| 06 | F | forward local failure with the retained rollback revoked | `rollback-refused/repair-required` |
| 07 | Q | `Recover` the row-06 root without changing any input | `rollback-refused/repair-required` |
| 08 | N | V0 successful `Apply` on a different fresh root | `committed/committed` |
| 09 | P | same as row 02 on a fresh root | `resource-denied/release-accepted` |
| 10 | I | same as row 03 on a fresh root | injected interruption; coherent state `staged` |
| 11 | R | `Recover` the row-10 root | `recovered/staged` |
| 12 | B | same as row 05 on a fresh root | `rolled-back/rolled-back` |
| 13 | F | same as row 06 on a fresh root | `rollback-refused/repair-required` |
| 14 | Q | `Recover` the row-13 root | `rollback-refused/repair-required` |
| 15 | N | V0 successful `Apply` on a different fresh root | `committed/committed` |
| 16 | P | same as row 02 on a fresh root | `resource-denied/release-accepted` |
| 17 | I | same as row 03 on a fresh root | injected interruption; coherent state `staged` |
| 18 | R | `Recover` the row-17 root | `recovered/staged` |
| 19 | P | same as row 02 on a fresh root | `resource-denied/release-accepted` |
| 20 | S | V0 successful `Apply` on a fresh root | `committed/committed` |

Thus the 100 calls contain exactly `20` successful fresh-root updates, `20`
pre-stop refusals, `15` injected interruptions, `15` paired recoveries, `10`
safe rollbacks, `10` rollback refusals, and `10` stable repair inspections.
The global first and last invocations are byte-exact V0 successes. Rows 08, 15,
and 20 demonstrate return to a valid update only on a different fresh root;
neither `Apply` nor `Recover` transitions a repair-required root back to work.

The injected interruption is the already accepted per-invocation test seam. It
is not a production error value. The test independently verifies the durable
`staged` prefix before calling `Recover`.

### A3 — exact physical and counter oracle

After every return, the test performs one independent bounded walk of only the
declared update root. It does not use a production result constructor or
production inventory helper as its oracle. The sample contains:

```text
allocated regular-file bytes
owned entry count
payload directory count
staging payload count
journal entry count
unowned temp count
test-owned open handle count
test-owned live goroutine count
test-owned live timer count
test-owned live child-process count
bounded result projection bytes
```

The row invariants are exact:

| Code | Payloads | Staging | Journal entries | Unowned temp |
|---|---:|---:|---:|---:|
| S, N | `2` (candidate current + predecessor rollback) | `0` | `9` | `0` |
| P | bootstrap predecessor only; root otherwise byte-identical | `0` | `0` | `0` |
| I, R | `1` (bootstrap current) | `1` | `3` | `0` |
| B | predecessor current only | `0` | `10` | `0` |
| F, Q | failed candidate current + predecessor rollback | `0` | `10` | `0` |

Every row also satisfies the accepted global ceilings: one current, at most one
rollback, at most one staging payload, one active transaction, at most `16`
journal entries of at most `4,096` bytes, activation record at most `16,384`
bytes, and any copy-on-write fixture at most `67,108,864` bytes and `4,096`
entries. A discrepancy between this table and an accepted predecessor task is
`contract-blocked`; M3 may not alter the table or production format to make the
test green.

The result projection is a test metric, not a public encoding:

```text
len(Outcome) + len(State) + 8 + 32 + 32 + 1
+ len(SafeNotice) + len(CustodyNotice)
```

It is at most `1,152` bytes. All four test-owned runtime counters are exactly
zero after every invocation; no child process is created by 08a. For each row
position, allocated bytes, entry counts, result projection bytes, Adapter call
counts, and terminal counter values must be exactly equal in all five blocks.
This equality makes the last 20 invocations equivalent to the preceding four
blocks and permits no upward trend to be hidden by averaging.

The harness removes a root only after its sample and after proving that no
test-owned handle, goroutine, timer, or child process remains. Temp-directory
removal is harness cleanup, not Update Transaction evidence; durable I/R and
F/Q residue is deliberately sampled before removal.

### A4 — cleanup deadline semantics

Separate table-driven tests exercise cleanup independently of the 100-call
campaign. Cleanup uses the accepted shared continuation of at most five
seconds. The monotonic deadline is checked immediately before and immediately
after every cleanup operation. Exact boundary is allowed; first observation
later than the deadline fails. No operation starts after expiry.

| Observation | Required result |
|---|---|
| all declared cleanup operations finish at or before the boundary | preserve the primary bounded outcome and exact zero undeclared residue |
| an operation returns nil after the boundary | `cleanup-incomplete/<last coherent state>`, non-nil error, never committed |
| an operation fails before the boundary | `cleanup-incomplete/<last coherent state>`, non-nil error, remaining evidence preserved |
| context is already cancelled when safety cleanup starts | a separate at-most-five-second safety continuation is still used; it does not extend any authenticated deadline or retry work |

The test uses a deterministic monotonic clock and operation counters; it has no
sleep. It proves exactly one attempt per declared operation, deepest-first
lexical ordering, parent durability acknowledgement after successful child
removal, and no later operation after failure or overrun.

### A5 — full D0 sentinels

Before and after every invocation, independent test fixtures hash and compare
the exact bytes of:

- Authority Vault and authority signing watermarks;
- Release Safety/build/protocol floors;
- Network Epoch and Namespace current records;
- Grants and credential files; and
- Endpoint identity state.

All are byte-identical. Counters prove zero Authority mutator calls, zero secret
reads, zero floor-lowering calls, no new-work admission after a successful
`StopNewWork`, and no internal activation retry. Expected writes are confined
to the one declared fresh update root. A D0 mismatch reports the first block,
row, sentinel, and owning resource without printing secret bytes.

## S7.2-08b — complete same-root C10 campaign

08b remains `contract-blocked`. Before any implementation brief or factual cap
can be accepted, Codex must freeze the following engineering decisions in an
authoritative format amendment; Product Owner acceptance is still required for
the implemented slice and any product-scope change:

1. **Journal retirement:** the exact durable proof that permits an immutable
   terminal transaction journal to be retired; what commitment to the retired
   chain survives; crash points before/after retirement; corruption behavior;
   and the maximum retained completed journals.
2. **Ordinal and generation:** separate canonical rules for monotonically
   increasing transaction ordinal and payload generation, including failed,
   rolled-back, repair-required, recovered, and idempotent invocations. Neither
   value may be reset merely because files were compacted.
3. **Repair-required:** no normal same-root update transitions out of
   `repair-required`. The accepted owner repair/export procedure must name the
   new root or replacement operation and the evidence retained from the old
   root.
4. **Schema-owner compaction:** for each maintained S7.2-06 schema owner, exact
   current/predecessor retention, selection commitment, foreign-content
   deletion authority, crash recovery, and first-excess behavior. A test-only
   generic fixture is not a production owner rule.
5. **Contributor compaction:** after S7.2-07, the exact Network State floor that
   proves a retired assignment cannot again be current, the bounded episode
   record that survives replacement, and native process/handle terminal
   evidence. Update Transaction must not delete `localroles` state.
6. **Logs and runtime resources:** the owner of process, handle, goroutine,
   timer, and bounded diagnostic-log counters on Installed and Portable
   surfaces, plus the native Ubuntu 26.04 Desktop and Windows 11 evidence
   commands. Windows installation remains prohibited without a separate
   Product Owner command.

Only after those rules and S7.2-02 through S7.2-07 are accepted may Codex take
a factual file/LOC inventory and freeze 08b caps. 08b must then repeat the
accepted equivalent 20-row cycle five times on one eligible owner root (using
an explicit accepted new-root operation for any repair-required row), prove
bounded retirement/compaction, run native clean-host evidence, and close C10.
No M3 session, code change, or S7.2-08 status change is authorized by this
proposal.
