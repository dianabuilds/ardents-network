## Accepted Product Owner decisions

Acceptance of this brief jointly freezes four amendments:

1. the five-second cleanup rule means that no new cleanup operation starts
   after budget expiry; an already-running non-cancellable kernel operation
   may return later, its overrun is observed, and the result is
   `cleanup-incomplete`;
2. S7.2-02 replaces the S7.2-01 create-new/remove lock with the permanent,
   bootstrap-created empty OS-locked file under the already-owned root specified
   below;
3. `Recover` outcomes, R00-R14 normalization, and the invalid corpus below are
   the exact S7.2-02 oracle;
4. the private per-invocation interruption seam below is permitted only for
   exercising real `Apply` orchestration, and the private per-invocation
   recovery-operation seam is permitted only for deterministic cleanup and
   durability faults; the public Interface stays frozen.

All four decisions are accepted. The acceptance commit amends the S7.2 task
contract and transaction-format proposal; only that resulting SHA becomes the
implementation baseline.

## Frozen recovery outcomes

| Observation | `Outcome` | `State` | Error | Fixed safe notice |
|---|---|---|---|---|
| coherent nonterminal prefix | `recovered` | exact last durable state, or `idle` when no entry exists | `nil` | `update interrupted` |
| coherent complete transaction | `committed` | `committed` | `nil` | exact committed manifest notice |
| another live owner holds the root | `resource-denied` | `busy` | non-nil | `update transaction busy` |
| cleanup/normalization fails or overruns | `cleanup-incomplete` | last coherent journal state | non-nil | `update cleanup incomplete` |
| corrupt, contradictory, aliased, or ambiguous evidence | `transaction-invalid` | `transaction-invalid` | non-nil | `update transaction invalid` |

For `recovered`, `Generation` is the interrupted transaction generation,
except `idle`, which reports the selected current generation. Current,
rollback, and staging fields reflect the normalized physical selection.
`CustodyNotice` is read from the selected current manifest, never from a
candidate summary. Invalid and busy results expose `Generation=0`, zero
current/rollback digests, `StagingPresent=false`, and an empty custody notice.
`cleanup-incomplete` retains the known transaction generation and last coherent
journal state but exposes zero current/rollback digests, false staging, and no
custody notice. An atomic operation may have completed while its
durability acknowledgement failed, so no second inspection or bounded summary
pretends to resolve that uncertainty. Every dynamic OS error remains outside
bounded notices. The non-zero transaction generation with zero physical
selection fields is deliberate: it reports only already-verified journal
identity and makes no claim about a partially normalized filesystem.

## Crash-owned lock rule

Installer/portable-root bootstrap and every amended V0 fixture create the
initialized empty lock file before transaction use. `Apply` and `Recover` use
one private acquire operation that securely opens that existing file and then
takes a non-blocking operating-system exclusive lock on the handle for the
whole owned-root operation. They never create or repair it. The path remains
`.ardents-update-transaction-lock`. Starting with S7.2-02 it is a permanent
admitted root child and is never unlinked by normal teardown, invalid recovery,
or cleanup.

- Under the already-owned update root, acquisition performs exactly one open
  attempt with no create or retry. Missing, disappeared, or identity-changing
  lock evidence is `transaction-invalid` without mutation. The handle admits
  only the exact direct regular, empty, single-link lock file, then verifies
  after OS-lock acquisition that it still names the current path inode/file
  identity. Windows owner/DACL admission remains S7.2-03 work.
- A process crash may leave the file, but releases the OS lock.
- Lock busy returns the frozen `resource-denied` result without mutation.
- Teardown finishes every root operation, then unlocks and closes the permanent
  handle. It never removes or replaces the path. This forbids the old-inode /
  new-inode split-brain possible with an unlinked lock file.
- An alias, reparse point, malformed file, unsupported lock primitive, or lock
  error is not treated as a stale owner and fails closed.

Every R00-R14 checkpoint includes the same direct regular single-link
permanent lock file with no live OS lock. It is reused for ownership and is not
incomplete journal evidence. The busy mutation holds the live OS lock and is
not a checkpoint.

Use the standard library on non-Windows and the already-recorded
`golang.org/x/sys/windows` dependency on Windows. Add no dependency and expose
no lock Interface.

## Frozen checkpoint table

The independent test constructs every row from saved V0 facts and literal
binary records. A complete entry means the exact canonical bytes and complete
predecessor chain are present. Presence of an executable, directory, process
exit, candidate summary, or non-canonical record is never successor evidence.

| ID | Last complete journal prefix | Physical state on entry | Required result and normalization |
|---|---|---|---|
| R00 | none | predecessor `current`; empty transaction/journal directories | remove only both empty directories; return `recovered/idle` |
| R01 | `release-accepted` | predecessor current; no staging | preserve exact prefix; return `recovered/release-accepted`, no staging |
| R02 | `artifact-verified` | predecessor current; no staging | preserve exact prefix; return `recovered/artifact-verified`, no staging |
| R03 | `artifact-verified` | predecessor current; complete candidate in staging but no `staged` entry | remove only that exact unacknowledged staging candidate; preserve prefix; return R02 |
| R04 | `staged` | predecessor current; exact candidate in staging | preserve both; return `recovered/staged`, staging present |
| R05 | `rollback-reserved` | same selection and staging | preserve; return `recovered/rollback-reserved` |
| R06 | `stop-new-work` | same selection and staging | preserve; return `recovered/stop-new-work` |
| R07 | `draining` | same selection and staging | preserve; return `recovered/draining` |
| R08 | `draining` | candidate moved to generations; predecessor current; no current temp | move that exact unselected candidate back to staging; return normalized R07 |
| R09 | `draining` | candidate moved; predecessor current; exact complete direct regular single-link successor current temp | remove exact temp, move candidate back to staging; return normalized R07 |
| R10 | `draining` | post-replace crash resolved to complete successor current with predecessor as rollback | verify and durably restore the canonical predecessor current first, then move the exact candidate back to staging; return normalized R07 with interrupted candidate generation, predecessor current digest, zero rollback digest, and staging present |
| R11 | `draining` | successor current durably acknowledged but no `activated` entry | normalize and return the exact R10 result; current-file presence alone is not activation acknowledgement |
| R12 | `activated` | successor current, predecessor rollback, candidate generation, no staging | preserve; return `recovered/activated` |
| R13 | `self-testing` | same successor selection | preserve; return `recovered/self-testing` |
| R14 | `committed` | coherent successor selection and exact nine-entry chain | return the unchanged V0 committed result |

The before/after tests for all nine state publications map to the adjacent
prefix rows: before state `N` equals the complete prefix through `N-1`; after
acknowledged publication equals the prefix through `N`. A post-replace crash
that resolves to the complete predecessor current is observationally identical
to R08 and is covered by R08; recovery never invents unobservable provenance.
R08-R11 additionally
cover generation publication, current-temp publication, atomic replacement,
both permitted post-crash filesystem outcomes, and durability acknowledgement.

“V0 passes unchanged” freezes its canonical record bytes, commitments, public
Result, and command JSON. The accepted S7.2-02 format amendment intentionally
adds the permanent lock file to the physical idle and committed root oracle;
its empty bytes are not hashed into V0 records or Results.
R00's “empty” qualification applies only to the named transaction/journal
directories; the permanent lock is the sole additional admitted child.

For R10/R11, `Recover` reconstructs the predecessor `current` only from the
successor record's exact rollback tuple: selected transaction equals that
rollback generation, current equals that tuple, and rollback is absent. It
reconstructs the exact canonical predecessor-inspection envelope defined in
`stage-7-s7.2-transaction-format-proposal.md` section 9 from those current bytes,
their decoded tuple, and the independently verified predecessor artifact and
manifest bytes. Its SHA-256 must equal entry 1's predecessor commitment before
any replacement or move. A mismatch is `transaction-invalid` with no mutation.

## Frozen invalid and cleanup corpus

Each mutation returns `transaction-invalid`, preserves every byte, calls no
Adapter, and does not remove or replace the permanent lock file:

- malformed, partial, gapped, duplicated, extra, or out-of-order entry;
- broken first predecessor or later predecessor commitment;
- decreasing observation, extended deadline, wrong generation, artifact, or
  manifest commitment;
- missing selected predecessor or candidate;
- candidate simultaneously in staging and generations;
- successor current before activation with no exact rollback predecessor;
- predecessor current with an `activated`, `self-testing`, or `committed`
  prefix;
- successor current with only a pre-`draining` prefix;
- missing permanent lock, reused generation, second transaction, unknown root
  child, current temp with wrong name/bytes, symlink, junction, reparse point,
  or hard link.

The cleanup allowlist contains only: R00 empty transaction directories, R03
exact unacknowledged staging, R09 exact direct regular current temp, and the exact reversible
candidate placement in R08-R11. A malformed or merely unexpected object is
never deleted. No new cleanup operation starts after the five-second
continuation budget expires. An in-flight non-cancellable kernel operation may
return later; the overrun is observed, no subsequent operation starts, and the
result is `cleanup-incomplete`, never `committed`.
The planner orders row operations exactly left-to-right as written above;
within an admitted tree it uses deterministic deepest-first lexical path order,
and each required parent sync is the next separate step. It checks the budget
immediately before every remove, move, replace, and sync step. Thus a test can
freeze the exact completed prefix when any chosen step blocks past the budget.
