## Fixed implementation shape

1. Keep the external Interface deep: complete `Apply`, terminal `Recover`, one
   bounded `Result`, and the accepted dependency types only. `Request` carries
   injected `WorkControl` and `SelfTest` Adapters. `Apply` must not construct,
   replace, type-assert to, or bypass either Adapter.
2. Keep all owned-root, journal, payload, locking, inventory, and cleanup logic
   in shared files. The two durability files contain only the genuinely
   platform-specific atomic replacement and durability primitives. Do not
   duplicate a platform store.
3. Keep at most one narrow private durability seam. Do not reproduce the
   abandoned nine-method `storeAdapter` or expose a generic filesystem
   Interface.
4. Store each durable state as a distinct immutable bounded journal entry.
   `journal.go` owns its explicit versioned binary codec and imports its own
   `encoding/binary` and `errors` dependencies. For each entry after the first,
   the predecessor field is SHA-256 of the exact preceding entry bytes. The
   first entry commits the exact inspected predecessor terminal state. Never
   overwrite a prior entry with its successor.
5. Stage the verified manifest and payload once. Activation moves that already
   complete staging directory into its generation and atomically replaces only
   the current selection record. Do not rewrite the moved manifest. Do not
   delete the selected active generation before replacement.
6. Detect an identical committed request before generation allocation,
   staging, Adapter calls, or journal creation. Return its original generation
   and terminal facts. A conflict never reuses that generation.
7. Require the previous payload together with the V0 stored authorization;
   arbitrary previous bytes are not rollback authorization.
8. Observe every cleanup, close, sync, and atomic-publication error. Bound
   failure cleanup by `5 s`; never discard it with `_ =` or an errorless close.
9. D0 is test evidence, not a notice. The injected self-test fake captures
   only the bounded candidate identity and independently held custody probes.
   It proves exact floor bytes, unchanged Vault and authority-watermark
   commitments, zero secret reads, and zero Authority mutations.
10. Use V0 unchanged. Expected result values and hashes come from the saved
    vector, never from production encoders, validators, hash helpers, or result
    summaries.

## Required acceptance tests

The exact names may follow repository naming conventions, but the final handoff
must map every contract criterion to one of these concrete behaviors:

1. V0 through `releasedecision` and `apply-offline` returns the exact frozen
   `ardents-update-result-v1` JSON.
2. V0 `Apply` crosses all nine states and produces a complete immutable
   predecessor-commitment chain checked from raw entry bytes by test code.
3. Reads select the previous payload before activation and the candidate only
   after committed current-record publication; rollback is the exact previous
   payload and staging is absent.
4. Payload/manifest mutation through the Interface is impossible and external
   mutation is detected on inspection.
5. Counter Adapters prove exactly one `StopNewWork`, one `Drain`, and one
   candidate-identity self-test call.
6. D0 probes prove byte-identical Decision floors and custody commitments, zero
   secret reads, and zero Authority mutations.
7. Running the identical V0 request twice returns generation `1` twice and the
   second call changes no payload, staging, journal, current record, or Adapter
   counter.
8. Activation succeeds with the manifest already present in staging and never
   performs delete-before-replace or a second exclusive manifest creation.
9. Injected cleanup/close failure is visible as bounded non-success within the
   cleanup ceiling.
10. One table-driven Interface test rejects oversized candidate, missing stored
    rollback authorization, and occupied staging before stop/current mutation.
    Do not implement the wider S7.2-03 fault taxonomy in this task.
