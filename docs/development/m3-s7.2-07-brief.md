# Proposed contract amendment — S7.2-07 Contributor update lifecycle

Status: **engineering analysis accepted by Codex under the Product Owner's
standing Stage 7.2 delegation; contract-blocked as one complete implementation
and not authorized for MiniMax M3.** Routine Interface/cap decisions below need
no further confirmation. A complete implementation brief still requires
S7.2-06 acceptance, the selected Installed bootstrap process/control ownership
that materially affects product behavior, and an exact baseline plus factual
post-S7.2-06 inventory.

## Why the current task is contract-blocked

The S7.2-07 user story and C11 evidence remain required. They cannot currently
be implemented faithfully through the maintained runtime:

- `updatetransaction.Request` carries only one topology-free `ActiveWork`
  observation and the `WorkControl` seam has only `StopNewWork` and `Drain`;
- `Recover` deliberately receives no Adapter and therefore cannot inspect a
  surviving role, process, handle, identity, assignment, or credential;
- `cmd/ardents-release apply-offline` supplies only the zero-work
  `stoppedRuntime`; it has no control channel to a live Contributor;
- `node.Run` privately owns one role-probe listener until terminal return and
  exposes no caller-owned stop/drain handle;
- the maintained Contributor commands have no selected supervisor, service
  manager protocol, or authenticated local IPC through which an updater can
  stop and replace their processes;
- the current Node projection has epoch and record bounds, but no complete
  per-role local, release-transition, credential, assignment, and Work Safety
  Lease tuple;
- `localroles` persists live conflict facts but deletes them on terminal exit;
  it has no assignment-bound terminal/non-revival inventory; and
- current production represents one admitted Node duty, so the fixed two-role
  row cannot be a live production claim merely by running two test fakes.

Adding role arrays to `updatetransaction.Request` or `Result`, adding `Rejoin`
to its Interface, or widening journal v1 would put caller-owned topology and
authority policy into the wrong Module. Those changes are rejected. A fake-only
two-role test also cannot satisfy C11 or the cross-platform G7 evidence gate.

The smallest faithful resolution is the two-part split below. S7.2-07 remains
open until both parts are implemented and accepted; S7.2-07a alone is
development evidence, not completion of the original user story.

## D1 — unchanged Update Transaction Interface and format

`internal/updatetransaction` retains the accepted external Interface:

```go
type WorkControl interface {
	StopNewWork(context.Context) error
	Drain(context.Context) error
}

func Apply(context.Context, Request) (Result, error)
func Recover(context.Context, string) (Result, error)
```

`Request`, `Result`, `CandidateIdentity`, `SelfTest`, journal v1, manifest
versions, current selection, and every already accepted outcome remain
unchanged. In particular:

- no role, endpoint, route, process, credential, assignment, epoch, lease, or
  terminal-inventory field crosses the Update Transaction Interface;
- `Result` remains topology-free and bounded;
- `Recover` performs only owned-root recovery and never opens Contributor
  state, starts a process, calls an Adapter, or guesses that a duty stopped;
- rejoin and withdrawal are not Update Transaction states or public methods;
  they occur only after committed code selection in the caller-owned
  Contributor lifecycle; and
- journal v1 records only the existing Update Transaction state and Adapter
  result. Per-role state is evidence owned by the Contributor Adapter.

For S7.2-07 the accepted range of `Request.ActiveWork`, if D1 is accepted, is
the literal integer `0..2`. It is the number of enumerated active role duties
captured by the concrete Adapter, not a count of connections or independent
security evidence. The Adapter rejects a mismatch before stopping admission.
This amendment changes no V0 byte: V0 remains `ActiveWork == 0`.

## D2 — responsibility and evidence ownership

One caller-owned concrete Contributor `WorkControl` Adapter owns the complete
per-role behavior behind the existing two-method seam. Ownership is exact:

| Fact or action | Owner |
|---|---|
| release outcome, Build Safety and protocol-transition bounds | current `releasedecision.Decision`; Update Transaction supplies only the already bounded transaction context |
| current Network Epoch, assignment and their authenticated terminal bounds | `internal/network/state` immutable `Snapshot`, derived from `internal/network/epoch` |
| local Node identity match, current assignment admission and role credential validity | `internal/node` using its current `Facts`, `Config`, and `internal/node/probe` plan |
| accepted connections, listener admission, process/handle closure | the concrete Contributor runtime and `internal/node/probe`; never inferred from a state file |
| active Endpoint-local duty and bounded terminal/non-revival evidence | a separately versioned Contributor update-episode store owned by `internal/localroles`; it is not the current duty JSON and is not selected by S7.2-06 `schema-current` |
| stop/drain sequencing and public transaction outcome | `internal/updatetransaction`, through the unchanged `WorkControl` seam |
| process replacement and post-commit restart | the selected Installed runtime supervisor/caller, not Update Transaction |
| fresh rejoin or withdrawal | the caller/Contributor lifecycle after a coherent `committed` result |

The Adapter may close over copied, already verified facts and owned runtime
handles. It receives no Authority root material, Bundle secret, signing key,
floor mutator, metadata parser, Network Epoch selector, or Namespace mutator.
There is no second role-policy implementation in Update Transaction.

The following are the only unavoidable narrow Interface changes outside Update
Transaction. Their exact Go spelling must be frozen with the accepted S7.2-06
schema/caller inventory before 07a is authorized:

1. `internal/node/probe.Server.Stop` and `Drain` must return an observed `error`
   instead of silently discarding listener-close, connection-close, timeout,
   and terminal-wait failures. Existing callers must consume those errors.
2. `internal/node` needs one caller-owned concrete control value, obtained from
   the same start operation that owns the role, whose only update-facing methods
   are the existing `StopNewWork(context.Context) error` and
   `Drain(context.Context) error`. It exposes no `probe.Server`, listener,
   endpoint, credential, identity key, or topology.
3. `internal/localroles` needs one atomic replace-and-read seam for the single
   bounded update episode defined in D4. It must update duties and episode
   evidence in one owner-state generation; separate best-effort writes are not
   allowed.

No generic role-controller Interface, exported role slice, callback registry,
supervisor abstraction, or `updatetransaction` declaration is authorized. If
the exact S7.2-06 schema cannot provide item 3 without another public type, that
type and its fields require a separate contract amendment before M3 sees code.

## D3 — exact role snapshot and deadline rule

Immediately before `StopNewWork`, the Adapter captures one immutable inventory
of zero, one, or two currently active roles. Each role has these private facts:

```text
role_key                 32 opaque bytes
assignment_digest       32 opaque bytes
epoch                    uint64
local_deadline           finite UTC instant
transition_deadline      finite UTC instant
credential_not_after     finite UTC instant
assignment_not_after     finite UTC instant
epoch_not_after          finite UTC instant
work_safety_not_after    finite UTC instant
```

`role_key` is an owner-local opaque identifier. It is not an endpoint, address,
role class, Route position, Node identity, or public identifier. Duplicate or
zero role/assignment identifiers, zero/non-UTC deadlines, more than two roles,
an `ActiveWork` mismatch, or an already expired bound fails `StopNewWork`
without claiming success.

The Update Transaction context already represents the minimum of the caller,
Build Safety, protocol transition, and the accepted S7.2-04 local ceiling. For
each captured role, `Drain(ctx)` independently uses:

```text
role deadline = min(ctx deadline,
                    local deadline,
                    transition deadline,
                    credential not-after,
                    assignment not-after,
                    epoch not-after,
                    Work Safety Lease not-after)
```

No absent value means infinity: every per-role bound is mandatory. The Adapter
does not resample a later deadline or let owner policy extend an authenticated
bound. It stops all role admission and durably acknowledges that fact before
`StopNewWork` returns nil. `Drain` may run at most two bounded role drains
concurrently so a short role is not queued behind a longer one. Completion of
one role never extends, retries, or changes another role's context.

A role deadline is checked before and after every terminal operation. A nil
return after expiry is failure. The Adapter leaks no goroutine, child process,
listener, connection, file/IPC handle, timer, or identity handle. If an owned
operation cannot be proved terminal by its deadline, the role is `expired`,
`Drain` returns non-nil, and Update Transaction cannot activate or commit.

The deadline inputs are not yet implementable from the maintained Interfaces.
`network/state.Snapshot.ValidUntil` and `RecordValidUntil` are available;
credential expiry exists only while building a probe; a per-role local deadline
and Work Safety Lease are absent; and a protocol-transition deadline may
legitimately be zero. Before 07a starts, an accepted amendment must map every D3
field to one exact owner and retained immutable fact, and must state whether an
absent protocol-transition bound is rejected or omitted from the minimum. M3
must not manufacture a deadline, reinterpret zero as infinity, or add fields to
Update Transaction to carry these caller-owned facts.

## D4 — exact private terminal inventory

The Adapter maintains one bounded, topology-free current update episode in a
separately versioned store owned by `internal/localroles`. It is not a migration
or reinterpretation of the current v1 duty JSON, does not use Update
Transaction's `schema-current`, and is not created by S7.2-06. Its exact root,
bootstrap, atomic replacement, permissions, recovery, and retention rules must
be accepted as a localroles Interface amendment before 07a starts. The episode
record contains exactly:

```text
version                    1
episode_generation         uint64, non-zero
candidate_digest           32 bytes
phase                      stopped | draining | terminal | rejoined | withdrawn
role_count                 uint8, 0..2
roles[role_count]:
  role_key                 32 bytes
  retired_assignment       32 bytes
  successor_assignment     32 bytes or zero
  effective_deadline       signed UTC Unix seconds
  stop_sequence            uint8, non-zero
  terminal_sequence        uint8, zero until terminal
  terminal                 completed | expired | interrupted | withdrawn
  admission_stopped        bool
  duty_closed              bool
  process_closed           bool
  handles_closed           bool
  identity_retired         bool
```

Records are sorted by `role_key`; duplicates, unknown enum/flag values,
non-canonical ordering, a terminal sequence before its stop sequence, a
successor equal to the retired assignment, or a terminal claim with any false
closure flag is invalid. The encoded episode is at most `4,096` bytes, has at
most two role records, and uses the localroles generation/watermark durability
rules. It contains no endpoint, network address, role class, Route topology,
credential bytes, secret, dynamic error text, or public diagnostic text.

`StopNewWork` publishes `phase=stopped` with `admission_stopped=true` for every
role before returning. `Drain` advances each record monotonically and publishes
`phase=terminal` only when all roles are terminal. Commit never deletes,
zeroes, or rewrites a retired assignment. Fresh rejoin may set only a distinct
`successor_assignment` and `phase=rejoined`; withdrawal sets
`phase=withdrawn`. A later episode replaces this bounded episode only after the
current Network State floor proves that no retained older assignment can again
be current. S7.2-08 must exercise that compaction rule under repeated updates.

The inventory is evidence of Adapter observations, not proof that an external
OS process died. S7.2-07b must correlate it with actual supervisor process and
handle observations before C11 can pass.

## D5 — crash, recovery, and non-revival

A process exit during `StopNewWork` or `Drain` leaves the last durably published
Adapter inventory unchanged. On restart:

1. public `Recover(updateRoot)` returns only the accepted transaction result for
   its last coherent journal prefix;
2. the Contributor owner independently opens and validates its terminal
   inventory and current Network State;
3. no role process starts and no assignment is admitted while the episode is
   `stopped`, `draining`, `expired`, or `interrupted`;
4. a crash during an Adapter call cannot create the next Update Transaction
   journal acknowledgement; and
5. continuation requires a later explicit owner operation with a live bounded
   context. There is no startup retry, background rejoin, or Application work
   replay.

Because journal v1 records a successful Adapter transition only after the call
returns, a crash during role drain leaves the last complete Module prefix at
`stop-new-work`; `Recover` therefore returns `recovered/stop-new-work`. It does
not return `committed`, reinterpret the private inventory, or clear it.

After committed code selection, rejoin reads new current facts. A cached
Decision, pre-update Snapshot, retained credential object, previous assignment,
or terminal inventory can never authorize it. The caller reevaluates current
Release Safety and Build/Protocol eligibility through `releasedecision`, then
reads one atomic current `network/state.Snapshot`; `internal/node` rechecks the
current identity, assignment, epoch/record validity, role credential, placement,
and Work Safety predicates. Only a distinct fresh eligible assignment may
start. Otherwise the role stays stopped; an explicit bounded withdrawal may
retire its owner state. Neither path revives the retired assignment.

## D6 — frozen nine-row oracle

The Module columns are the only public Update Transaction result. Adapter
outcome/state and inventory remain private Contributor evidence.

| Row | Fixed observation | Module `Outcome/State` | Adapter outcome/state | Exact terminal selection |
|---|---|---|---|---|
| 1 | zero roles | `committed/committed` | `drained/no-roles` | empty terminal role array; no process or handle created |
| 2 | one role completes before every bound | `committed/committed` | `drained/terminal` | one `completed` record; all five closure flags true |
| 3 | two roles have different effective deadlines and both complete | `committed/committed` | `drained/terminal` | two sorted `completed` records; each keeps its own deadline and terminal sequence |
| 4 | one of two roles is still live at its earliest deadline | accepted S7.2-04 `drain-expired/stop-new-work` | `drain-expired/partial` | completed role stays completed; other is `expired`; no activation or self-test |
| 5 | controller process exits during role drain | after restart `recovered/stop-new-work` | `interrupted/stopped` | last acknowledged per-role prefix retained; no automatic continuation or role start |
| 6 | post-commit current state repeats the retired assignment | prior Module result remains `committed/committed` | `rejoin-refused/stale` | successor remains zero; all roles stopped |
| 7 | post-commit facts contain a distinct fresh eligible assignment and current credential | prior Module result remains `committed/committed` | `rejoined/ready` | successor is the exact fresh assignment; retired assignment remains recorded |
| 8 | post-commit assignment is fresh but any Release, build/protocol, credential, epoch, placement, or Work Safety predicate is ineligible | prior Module result remains `committed/committed` | `rejoin-refused/ineligible` | successor remains zero; no listener/process/handle starts |
| 9 | owner explicitly withdraws after a refused rejoin | prior Module result remains `committed/committed` | `withdrawn/withdrawn` | terminal inventory remains, live duty set is empty, no role is restarted |

Rows 1-4 exercise `Apply`; row 5 exercises process exit plus public `Recover`;
rows 6-9 are post-commit caller/Contributor lifecycle observations and never
append an Update Transaction journal state. Any inventory corruption, unknown
row, count mismatch, stale snapshot race, or ambiguous process/handle state is
fail-closed, non-committed where the transaction is still open, and never
silently mapped to one of the success rows.

## D7 — faithful implementation split

### S7.2-07a — Adapter contract and in-process tracer

After S7.2-06 and the separate Contributor episode-store/deadline amendments
are accepted, 07a may implement and test:

- the unchanged `WorkControl` sequencing for `ActiveWork == 0..2`;
- the immutable role snapshot and per-role deadline calculation;
- atomic bounded terminal inventory and its restart/corruption rules;
- a concrete in-process Adapter over maintained Node/probe handles;
- rows 1-4 and the inventory half of row 5;
- fresh-fact decision logic for rows 6-9 without starting an external replaced
  process; and
- D0 probes and deterministic fake-counter Module tests.

07a does not prove process replacement, cross-process control, installed service
manager behavior, executable handoff, or G7. Its result is
`implemented, not accepted`; it cannot mark S7.2-07 or C11 complete.

### S7.2-07b — live Contributor process integration

07b remains `contract-blocked` until a separately accepted Installed runtime
decision names:

1. the owner that starts, stops, replaces, and observes Contributor processes;
2. the authenticated owner-only control transport or native service-manager
   operation used by the updater;
3. process identity, authorization, replay, timeout, crash, and stale-controller
   rules on Ubuntu and Windows;
4. how a committed executable selection becomes the exact restarted process;
5. how fresh Release Decision and Network State facts are acquired without an
   ambient network fallback; and
6. the exact clean-host G7 evidence and cleanup artifacts.

This is an Installed-runtime decision. Portable remains the stopped-runtime
replacement path: the owner stops the process, runs the portable binary/CLI
transaction, and starts the selected payload explicitly. Portable does not gain
a hidden supervisor or background control channel merely to close C11.

07b then implements the process half of row 5 and live rows 6-9 on Ubuntu 26.04
Desktop and Windows 11. Windows installation or service registration still
requires a separate explicit Product Owner command. No choice above may be
inferred from Docker, the current shell, or a test subprocess.

## D8 — D0 and test evidence

Every row captures independent pre/post SHA-256 commitments for Authority Vault
bytes, authority signing watermarks, release floors, Network Epoch and Namespace
current bytes, Grants, credential files, and Endpoint identity. Expected changes
are limited to the declared Update Transaction root, the accepted copy-on-write
Contributor terminal inventory, and live process/handle state. Tests prove:

- zero Authority mutator calls, zero secret reads, and no floor-lowering method;
- byte-identical D0 commitments outside the two declared owner roots;
- exact `StopNewWork`/`Drain` order and counts through public `Apply` fakes;
- independent per-role contexts, earliest-deadline arithmetic, late-nil failure,
  one role not extending another, and no goroutine/timer/handle leak;
- real probe admission refusal and connection drain for one role;
- two-role ordering without using production result constructors as the oracle;
- inventory restart, corruption, first-excess, atomic publication, non-revival,
  and S7.2-08-compatible bounded replacement;
- process-exit recovery with public `Recover` and no automatic role start; and
- fresh stale/eligible/ineligible/withdrawal rows with independently replaced
  current Decision/Snapshot fixtures.

07b additionally requires real process-tree and handle inventory on both clean
hosts. A Go subprocess test or Docker-only run is development evidence, not a
Windows Installed or clean-host qualification result.
