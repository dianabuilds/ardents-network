# Proposed amendment and M3 briefs — S7.2-09 independent update evidence

Status: **engineering contract accepted by Codex under the Product Owner's
standing Stage 7.2 delegation; implementation remains contract-blocked.** This
document freezes the producer/verifier split. Neither part may start until every
blocking predecessor and the byte registry in this document are closed in an
implementation-authorizing commit. Product Owner acceptance remains required
for each completed slice and final S7.2 disposition, not for routine
implementation shaping or factual cap amendments.

The implementation tags are `M3-autonomous`, one fresh writer context per
part. The independent review tag is `M3-after-contract` in a third context that
implemented neither part nor any S7.2 candidate task. Codex retains Standards
and Spec review; only the Product Owner may accept either part or S7.2.

## Why the accepted task needs this amendment

The authoritative S7.2-09 task requires an independent `pass|fail|invalid`
verdict but permits only a verifier package and command. It does not identify
who creates the immutable manifest and raw evidence consumed by that verifier.
Letting `internal/updatetransaction`, its tests, or the verifier itself create
the complete oracle would collapse candidate, evidence, and verdict authority.

S7.2-09 is therefore two sequential tasks:

1. **S7.2-09a — immutable C/D evidence producer.** It runs the accepted public
   candidate surface, captures raw facts, and publishes manifest/evidence
   commitments. It has no verdict authority.
2. **S7.2-09b — independent C/D verifier.** It separately decodes the accepted
   bytes, recomputes the predicates, and exclusively publishes the verdict.

The split does not add product code or a product-readable inspection API.
`internal/updatetransaction/view` is explicitly rejected: a verifier-facing
subpackage would expose private implementation state and make the verifier
dependent on candidate interpretation. S7.2-09b must never import
`internal/updatetransaction`, call its validators, or copy its decoder.

## Shared frozen authority and root layout

One run uses four newly created, mutually disjoint, non-link roots outside Git.
The caller supplies their absolute paths; no root may exist before its owning
publication step, overlap another root, contain another root, or resolve across
a link, reparse point, mount substitution, or volume boundary.

```text
private/fixtures/<ordinal>                 producer-only canary inputs
manifest/campaign.json                     frozen before candidate execution
manifest/hosts/<ordinal>.json              platform and observer identity
manifest/cells/<ordinal>.json              C0-C11 and D0 cases/predicates
evidence/index.json                        immutable artifact commitments
evidence/hosts/<host>/controls/<stream>.jsonl
evidence/cells/<cell>/attempts/<attempt>/observations/<stream>.jsonl
evidence/cells/<cell>/attempts/<attempt>/terminal.json
evidence/cells/<cell>/attempts/<attempt>/cleanup.json
verdict/verdict.json                       verifier-only output
```

The producer creates `private`, `manifest`, and `evidence` and never receives a
verdict-root handle. The candidate receives only one bounded case input, its
released fixture bytes, and its private temporary roots; it receives no
manifest-root or evidence-root write handle and no expected verdict. The
verifier opens the three committed input roots read-only and creates the
previously absent `verdict` root and `verdict.json` with exclusive creation.
Neither producer nor candidate may reopen, replace, append, or delete a
published input. OS Owner or host compromise can still delete or rewrite
same-account files; the profile detects that contamination but does not claim
the filesystem is a security boundary against the Owner or OS.

Every single-object file is the exact canonical JSON byte format accepted for
S7E1; every JSONL record has exactly one LF. All relative paths are derived by
the verifier from admitted ordinals. The accepted R-054 stable-read, canonical
encoding, path, identity, digest, and root-separation rules apply unchanged.

## Blocking format registry

Implementation is `contract-blocked` until an accepted S7E1 update-subset
registry freezes every byte read or written above. The registry is drafted only
after the accepted S7.2-06 implementation fixes journal/schema versioning and
is finalized after S7.2-07 and S7.2-08 fix role and pressure observations. It
must name, for every schema:

- literal schema/profile version, exact Go-independent field order and allowed
  enum values;
- maximum encoded size, count, ordinal rules, owner, and derived path;
- which fields are structural evidence and which raw facts feed a predicate;
- the exact C0-C11/D0 case and attempt inventory, expected runtime class, and
  required observation streams; and
- compatibility: unknown version or field is `invalid`; there is no silent v1
  to v2 coercion.

The registry describes bytes, not Go declarations. The verifier owns a private
decoder written from that accepted description. Sharing candidate structs,
generated encoders, schema packages, journal parsers, constants, validators,
golden builders, or `internal/updatetransaction/view` is forbidden.

## S7.2-09a — immutable evidence producer

### Responsibility and Interface

Add `internal/lab/updateevidence` and the thin command
`cmd/stage7-update-evidence-lab`. The Module owns one bounded, deterministic
C0-C11/D0 development run: precommit the complete scheduled subset, execute
each case once through accepted public production seams, capture independent
pre/post physical facts and injected call counters, publish immutable raw
evidence, and clean its private staging. It never reduces evidence to a
verdict.

The command has one operation:

```text
stage7-update-evidence-lab run \
  -manifest-root <new-absolute-root> \
  -private-root <new-absolute-root> \
  -evidence-root <new-absolute-root> \
  -work-root <new-absolute-root> \
  -candidate <absolute-preverified-executable>
```

It writes exactly one canonical producer result plus LF to stdout containing
only schema, run ID, campaign SHA-256, evidence-index SHA-256, scheduled count,
pending count, deferred count, and producer status
`published|producer-failed`. Exit is `0` only for `published`, `1` for a
bounded run failure, `64` for invocation/arguments, and `74` when an otherwise
complete bundle cannot be exclusively or durably published. Stderr contains
only fixed diagnostic codes. No output field may be
named or contain `pass`, `fail`, or `invalid`; a producer failure means only
that no trustworthy complete input bundle was published.

`work-root` is always removed before successful evidence publication. The
command accepts no `-verdict`, expected-result, retry, replacement, dynamic
cell-selection, network-source, or candidate-summary flag. The exact coverage
partition is manifest-bound before the first candidate call. A failed run is
retained under its run ID and cannot be replaced by a favorable rerun; a new run
uses a new ID.

### Required evidence behavior

1. The manifest binds source/candidate/tool/observer identities, four root
   identities, all accepted decision/format IDs, limits, clocks, exact cells,
   attempts, fixtures, expected runtime classes, raw predicates, and streams,
   but never an expected verifier result.
2. Candidate results and journal bytes are evidence inputs, not truth. The
   producer also captures pre/post update-root inventory, payload identities,
   current/rollback/schema-selection facts, monotonic deadlines, Adapter call
   observations, Vault/Authority/floor byte commitments, role/process survivor
   inventory, and cleanup/resource observations required by C0-C11 and D0.
3. The producer never reads Vault secrets or Authority root material. D0 uses
   precommitted opaque byte commitments plus zero-read/zero-mutation counters
   owned by the fixture Adapter.
4. Every artifact is length- and SHA-256-bound in `evidence/index.json`; stable
   identity is checked before and after reading; publication is exclusive,
   flushed, and directory-durable where the accepted platform seam supports it.
5. Candidate exit/log/summary cannot omit, replace, classify, or author a raw
   observation. An observer failure makes producer publication unavailable; it
   never produces a partial bundle presented as complete.
6. The package and command contain no verdict type, verdict status constants,
   predicate reducer, or verdict-root path. A repository test rejects those
   authority leaks.

### Frozen acceptance for 09a

- one byte-stable public V0/C0 bundle is produced identically for the accepted
  fixture on both verifier platforms except for manifest-bound native fields;
- all accepted S7.2 fixed tables have a precommitted case and required-stream
  entry, including expected refusal/repair results;
- interruption, post-stop, rollback, schema, role, pressure, cleanup, and D0
  fixtures publish the raw fact needed for an independent decision, not a
  candidate Boolean;
- attempted candidate/evidence/verdict-root overlap, post-publication write,
  missing observation, excess input, or observer failure cannot yield
  `published`;
- two runs with the same explicit frozen test inputs have byte-identical
  manifest/evidence content after excluding the manifest-bound random run ID
  and native identity fields; and
- focused tests, Linux build, Windows build, `go test -race`, `make quick-check`,
  and final `make check` pass, with any host/tool limitation reported rather
  than relabeled green.

### Scope and caps for 09a

- the `15` changed-file/`1,500` production-LOC values are a planning
  envelope only; after the registry is frozen, Codex records a factual
  responsibility inventory and accepts conjunctive task caps before Gate A;
- exactly one new Module and one new lab command; no product package or command
  Interface changes;
- every Go file remains at most `500` lines; production files above `250` lines
  require the accepted cohesion review;
- no dependency or `go.mod` change; the producer may import accepted production
  Modules needed to execute public seams plus the standard library;
- one factual `package-map.md` row per new package/command in the implementation
  commit; and
- no generated schema, evidence bundle, secret, log, capture, database, cache,
  build output, or host mutation artifact enters Git.

If the accepted registry and complete red oracle do not fit the factual
conjunctive caps, report `scope-blocked` without production commit. Do not
remove a cell, stream, mutation, platform fact, or cleanup check merely to fit
an estimate.

## S7.2-09b — independent verifier

### Responsibility and Interface

Only after 09a is accepted, add `internal/lab/updateverify` and the thin command
`cmd/stage7-update-verify-lab`. Production code is standard-library-only. The
Module independently admits the frozen roots, decodes every accepted byte with
its own private decoder, recomputes C0-C11/D0, and exclusively publishes one
bounded verdict. It imports neither `internal/updatetransaction` nor
`internal/lab/updateevidence`; tests use verifier-owned byte literals and invoke
the producer command only as an external black box when an end-to-end fixture
is required.

The command is exact:

```text
stage7-update-verify-lab \
  -manifest-root <read-only-absolute-root> \
  -private-root <read-only-absolute-root> \
  -evidence-root <read-only-absolute-root> \
  -verdict-root <new-absolute-root>
```

It writes the exact canonical `ardents-stage-7-update-verdict-v1` object plus LF
to stdout. The object contains, in accepted registry order: schema, campaign
SHA-256, evidence-index SHA-256, verifier executable SHA-256, status, coverage
counts, and fixed-code diagnostics. Exit is `0` only for `pass`, `1` for
`fail`, `2` for `invalid`, `64` for invocation/arguments, and `74` when the
verdict cannot be exclusively or durably published. Stdout is empty for `64`
and `74`; stderr has no raw platform error, path, secret, topology, or candidate
text.

### Verdict authority and precedence

1. **`invalid`** wins for malformed/noncanonical bytes; unknown schema/enum;
   missing/duplicate/reordered/unbound evidence; identity/hash/path/root/
   authority overlap; clock ambiguity; unavailable or contradictory required
   observer fact; secret/private-canary contamination; candidate verdict or
   summary substitution; count/size/time excess; or pre-existing/replaced
   verdict output.
2. **`fail`** follows only for a structurally complete and trustworthy bundle
   whose raw facts prove a functional, security, privacy, deadline, resource,
   platform, rollback, D0, role-survival, or cleanup contract violation.
3. **`pass`** requires every predicate true in every scheduled attempt. A
   scheduled `resource-denied`, `rollback-refused`, `rolled-back`, unavailable,
   or `repair-required` runtime result passes only in the exact case that
   requires it. Pending/deferred coverage is reported and never treated as a
   pass.

There is no warning, score, majority, favorable-cell offset, retry, expected
verdict field, or trust in candidate exit/log/summary. Admission, predicate
recomputation, cleanup, then exclusive verdict publication is the fixed order.

### Frozen mutation corpus

The verifier tests one valid V0/C0 bundle, every accepted fixed-table result,
and each mutation below as an independent oracle. Mutations are re-committed
with internally consistent artifact hashes when the row is intended to test a
behavioral `fail`; otherwise they test structural `invalid`.

| Mutation | Exact verdict |
|---|---|
| unknown/missing/duplicate/noncanonical field; schema/enum/version change | `invalid` |
| ordinal gap, duplicate or reorder; missing transition; duplicate generation | `invalid` |
| length/hash mismatch; broken predecessor; wrong candidate digest/identity | `invalid` |
| absolute/traversing/encoded/device path; link/reparse/hard-link/cross-volume leaf | `invalid` |
| root overlap; cross-run/cell/host substitution; pre-existing/replaced verdict | `invalid` |
| candidate-authored `pass`, summary in place of raw facts, missing/late/control-failed observer | `invalid` |
| secret/private-canary/plaintext Authority contamination; count/size/time excess | `invalid` |
| valid trace guesses commit or publishes an impossible transition | `fail` |
| staging mutation/failure after stop-new-work | `fail` |
| authenticated/local deadline extension or operation replay | `fail` |
| unsafe rollback or execution after rollback refusal | `fail` |
| schema selection switches before commit or prior schema becomes unreadable | `fail` |
| release floor decreases; Vault commitment or Authority watermark changes | `fail` |
| old Contributor role/process/handle survives or revives | `fail` |
| fourth payload, upward-trending bounded resource, or undeclared log growth | `fail` |
| proven candidate residue or cleanup deadline breach | `fail` |

Every structural mutation is exercised once on both verifier platforms; every
behavioral mutation is covered by a verifier-owned fixture. The verifier must
fail before reading beyond the applicable bound and must not disclose the
mutated secret/path/platform error in diagnostics.

### Frozen bounds and acceptance for 09b

R-054 bounds apply unchanged: at most `16,384` files, `128` logical cells, `64`
attempts per cell, `32` streams per attempt, `64 KiB` per JSONL record,
`128 MiB` per stream, `16 MiB` per manifest/index/terminal/cleanup object, and
`1 GiB` committed evidence. Verification must stream within `256 MiB` peak RSS
and `60 s` monotonic time and emit at most `256` fixed-code diagnostics totaling
at most `16 KiB`. Excess is `invalid` before unbounded allocation or partial
verdict publication.

Acceptance additionally requires:

- `updateverify` production imports only the standard library and an
  architecture test rejects imports of candidate/producer packages and any
  `internal/updatetransaction/view` path;
- the private decoder rejects every byte not admitted by the accepted registry,
  re-encodes admitted values, and compares byte-for-byte;
- the valid V0/C0 and every scheduled fixed table map to the independently
  expected status, while every mutation maps to the table above despite a
  successful candidate exit or summary;
- verdict publication is exclusive and bounded; inputs remain byte-identical;
- 100 canonical round trips of the synthetic maximum shape are byte-stable on
  both verifier platforms, and the `1 GiB` streaming gate is measured rather
  than inferred;
- focused tests, Linux build, Windows build, `go test -race`, `make quick-check`,
  and final `make check` pass, with native facts that are not available kept in
  the accepted coverage ledger; and
- Codex completes separate Standards and Spec reviews before the Product Owner
  is asked to accept the verifier or S7.2.

### Scope and caps for 09b

- the default file/LOC values are planning inputs only; after 09a and the
  registry are accepted, Codex records the independent decoder/reducer
  responsibility inventory and accepts factual conjunctive caps before Gate A;
- exactly one new verifier Module and one new lab command;
- every Go file remains at most `500` lines; production files above `250` lines
  require the accepted cohesion review;
- no dependency, generated codec, shared schema package, product Interface, or
  `go.mod` change;
- one factual `package-map.md` row per new package/command in the implementation
  commit; and
- generated evidence/verdicts, secrets, captures, logs, databases, caches, and
  build outputs stay outside Git.

If the complete independent decoder, oracle, and reducer do not fit the factual
caps, report `scope-blocked` without commit. Do not import producer/candidate
code or delete a mutation merely to satisfy an estimate.

## Explicit start blockers

S7.2-09a and 09b remain **NO-GO** until all of the following are true:

1. S7.2-01 through S7.2-08 are implemented, independently reviewed, Codex-
   reviewed, and Product Owner accepted; their complete C0-C11/D0 raw evidence
   requirements and frozen vectors are available.
2. The full S7E1 update-subset wire schema/version registry described above is
   accepted after S7.2-06 and finalized against S7.2-07/08; no format decision
   is delegated to M3.
3. Codex commits the complete two-part engineering contract, root/authority
   split, verdict table, commands, bounds, factual caps, and freshness rule in
   one implementation-authorizing baseline under the standing delegation.

09b starts only from the accepted 09a commit and accepted frozen public bundle;
it never consumes an unaccepted producer worktree. A fresh `M3-after-contract`
reviewer receives the accepted format, public corpus, baseline/final SHAs, and
command results, but no writer-session transcript or proposed fixes. Its output
is review evidence only: `worker-reviewed, not accepted`.

## Not in scope

Full Stage 7 acceptance; A/B/E/F/G cells; qualification on native surfaces that
remain authorization-pending or environment-deferred; an external independent
security audit; a product evidence API; exposing private transaction state;
repairing or rerunning candidate behavior; accepting candidate-authored
verdicts; or claiming same-account process separation resists Owner/OS
compromise.
