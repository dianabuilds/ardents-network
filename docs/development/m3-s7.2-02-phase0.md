Every normal recovery assertion and the busy test call public `Recover`.

encoded; production encoders, inspectors, planners, and Result constructors are
not the oracle. All coherent nonterminal rows use SafeNotice
`update interrupted`; custody comes from the selected current manifest. R14
uses the committed manifest notices.

## Accelerated isolated-worktree cycle

1. Codex creates one temporary worktree at the accepted baseline and launches
   the embedded MiniMax M3 coding-agent with repository tools.
2. In one implementation run, M3 builds the constructed red tracer, then the
   lock, inventory, policy, interruption, invalid, and cleanup slices in that
   order. It runs the focused package test after each green step and creates one
   commit only when the full contract and caps are satisfied.
3. Codex checks the physical worktree, commit, LOC, criterion/test map, and
   focused tests. Model prose is never evidence without matching files/output.
4. One fresh read-only M3 agent reviews the final commit. Material findings are
   returned once to the implementation worktree for an amend; Codex then runs
   one Standards/Spec review of the code, not of every planning step.
5. Codex runs controller cross-builds, race, quick-check, full check, and the
   authorized Ubuntu 26.04 clean-host tests before recommending acceptance.

M3 reports the actual baseline/final SHA and `implemented, not accepted` under
the existing collaboration contract. Codex remains the controller and the
Product Owner remains the sole acceptance authority.
