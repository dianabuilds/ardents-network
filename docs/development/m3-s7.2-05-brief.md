# Proposed M3-autonomous brief — S7.2-05a/05b self-test, rollback, and repair

Status: **engineering contract accepted by Codex under the Product Owner's
standing Stage 7.2 delegation; implementation remains blocked by S7.2-04.**
This combined brief becomes executable only after S7.2-04 is implemented and
accepted, the authoritative contract and format documents are amended in the
same implementation-authorizing commit, and Codex freezes factual post-S7.2-04
file and LOC caps.

The two task IDs and their C8/C5/C6/C9 evidence ownership remain distinct. They
are proposed as one atomic implementation slice because the unavailable retry,
new terminal states, rollback publication, and restart oracle change one journal
state machine and cannot safely be reviewed as unrelated partial formats.

## Why a combined amendment is required

The accepted task table states the intended behavior but the present Interface
and record format do not determine an implementation:

- `SelfTest.Check` returns only `error`; there is no machine-readable way to
  distinguish network unavailability from a local predicate failure;
- the current `Apply` collapses the Adapter error into a generic transaction
  failure, so a caller cannot retain the actual self-test evidence;
- the immutable `08-self-testing.entry` cannot be overwritten, so an explicit
  retry after an unavailable observation needs a separately frozen append rule;
- the Module has no current Release Decision for the retained payload and must
  not parse release metadata or treat an old manifest as current authorization;
- journal v1 has no codes for `rollback-pending`, `rolled-back`, or
  `repair-required`; and
- neither the terminal Result fields nor physical selection after rollback
  refusal/start failure are fixed.

M3 must not resolve these choices.

## Accepted engineering decisions

### D1 — one immutable unavailable error type

Add at most one exported declaration to the Module Interface:

```go
// SelfTestUnavailable is the immutable machine-readable observation that a
// normatively required network check could not complete.
type SelfTestUnavailable struct{}

func (SelfTestUnavailable) Error() string {
	return "self-test network unavailable"
}
```

The zero-field value is constructible by any `SelfTest` Adapter, carries no
mutable state or dynamic text, and is the only public classification addition.
There is no exported sentinel variable, constructor, enum, result subtype,
generic predicate map, or network Adapter. The error type says only that a
required network observation was unavailable. It never means that offline
predicates passed or that the candidate is safe.

`Apply` preserves the exact error tree returned by `SelfTest.Check`. Every
non-success return caused by that call includes the original error as an
`errors.Join` leaf; it is not replaced by its string or by a fresh generic
error. The unavailable classifier walks the complete standard Go error tree:

1. an exact `SelfTestUnavailable` leaf is unavailable;
2. a wrapper with `Unwrap() error` has the classification of its non-nil child;
3. a join with `Unwrap() []error` is unavailable only when it has at least one
   non-nil leaf and **every** non-nil leaf is unavailable; and
4. every unknown, local, deadline, cancellation, IPC, digest, schema, Vault,
   floor, or other leaf is failure.

Classification visits at most `16` non-nil error nodes and descends at most
`16` unwrap edges. A nil child is ignored. A cycle eventually exceeds that
bound. A panic from a caller-owned unwrap method or either bound being exceeded
classifies as local failure and never as unavailable. The implementation does
not require error-interface comparability or use the error as a map key.
Production does not render or persist dynamic error text. The oracle includes a
cycle, a non-comparable wrapper, and the first-excess tree.

Thus `errors.Join(SelfTestUnavailable{}, localFailure)` is a self-test failure,
not C8. Tests supply literal error trees and do not call the production
classifier to compute expectations. Recovery cannot reproduce dynamic Adapter
text; where it must report the durable unavailable state it returns a fresh
zero-field `SelfTestUnavailable{}` and no invented cause.

An offline-capable Adapter returns nil after all required offline predicates
pass even when no optional network observation is available. It returns
`SelfTestUnavailable{}` only when an online observation is normative for the
capability. This keeps capability policy in the caller-owned self-test Adapter
without widening `CandidateIdentity`.

### D2 — the caller supplies the retained payload's current decision

Add one field, but no new declaration, to `Request`:

```go
RollbackDecision releasedecision.Decision
```

It is the current, independently evaluated Release Decision for the exact
retained payload. It is not a historic decision saved beside that payload. The
caller obtains it through `releasedecision`; Update Transaction neither
re-parses metadata nor calls Release Decision itself.

Rollback is admitted only when all of these independently agree:

1. `RollbackDecision.Outcome` is exactly `release-accepted` or `no-update`, and
   `.BuildSafety` and `.Protocol` are exactly `release-accepted`;
2. its path, length, digest, platform, architecture, environment, network,
   release identity/version, build identity/state, protocol phase, and other
   authenticated identity fields equal the retained manifest authorization and
   independently rehashed retained bytes;
3. its `ReferenceTime` is non-zero UTC and is not earlier than the forward
   Decision's fixed reference time; its non-zero build/protocol bounds are
   internally valid, while D3 always keeps the earlier forward authenticated
   deadline in the effective minimum;
4. its complete four-role `releasedecision.FloorSet` equals the already
   committed forward Decision floor set field-for-field and digest-for-digest;
   Namespace, Network Epoch, freshness, exposure, Authority, and other
   foreign-owner watermarks are not `RollbackDecision` fields or rollback
   admission inputs and remain byte-identical D0 probes;
5. the accepted S7.2 schema plan says the not-yet-committed state is compatible
   with the retained payload; for this slice that is only `no-op-v1`; and
6. the retained artifact, manifest, stored authorization, current record, and
   first predecessor commitment remain coherent under the owned-root lock.

For item 1, `no-update` has the exact `releasedecision.Evaluate` meaning:
authentication succeeded and the candidate metadata floor set already equals
the committed floor set. It does not assert which payload Update Transaction
currently selects.

For item 5 in S7.2-05, compatibility is exactly
`Request.SchemaPlan == "no-op-v1"` and the retained manifest's plan is also
`no-op-v1`. S7.2-06 may amend that predicate only with its accepted schema
commitments.

Item 6 means all of the following independently hold:

- SHA-256 and length of retained artifact bytes equal the retained manifest;
- SHA-256 of the exact retained manifest equals its tuple in `current`;
- every stored authorization field equals the corresponding
  `RollbackDecision` identity, Build Safety, protocol, deadline, and four-role
  floor field;
- the retained generation equals the predecessor tuple in the selected current
  record; and
- the transaction's first predecessor commitment equals SHA-256 of the exact
  canonical predecessor-inspection envelope reconstructed from those bytes.

The frozen oracle adds one saved TUF set that contains both the forward and
retained target paths. Immediately before each public invocation, the caller
invokes `releasedecision.Evaluate` with the current saved root/metadata bytes,
the retained target path, exact independently read retained artifact bytes, the
same local binding, that invocation's fixed UTC reference time, and the same
durable floor store already used for the forward decision. The saved-set files,
their SHA-256 values, and the literal expected `Decision` are frozen before
Gate A. Until that public vector exists, S7.2-05 remains contract-blocked.

A zero, rejected, stale, mismatched, expired, revoked, below-floor, or otherwise
incomplete `RollbackDecision` refuses rollback before retained bytes are
selected or checked. The existing `apply-offline` V0 caller may leave this
field zero because its self-test succeeds and rollback is never consulted. The
V0 request behavior, journal bytes, Result JSON, and command exit remain
unchanged. Adding a rollback metadata CLI or parser is not authorized here.

### D3 — exact bounded self-test deadlines

For each actual call to `SelfTest.Check`, the Module captures a private
monotonic observation immediately before constructing the call context. The
forward effective deadline is:

```text
min(invocation caller deadline captured at Apply entry,
    forward Build Safety terminate time,
    non-zero forward protocol-transition deadline,
    self-test monotonic observation + 15 seconds)
```

The rollback-start effective deadline additionally includes the retained
decision's Build Safety terminate time and non-zero protocol-transition
deadline. `BuildSafetyNoNewWorkAfter` does not apply: new work has already been
stopped. A missing caller deadline is absent; a zero protocol deadline is
absent. An already-cancelled or expired context prevents the Adapter call and is
a self-test failure. After a call returns, `ctx.Err()` has priority over nil; a
late nil return cannot publish success or start another operation.

There is no goroutine wrapper, internal retry, replay, background continuation,
or direct/network repair. Each public invocation makes at most one forward and,
after failure, at most one rollback-start self-test call. Rollback activation
and its self-test use the same remaining bounded operation context and check
expiry before and after every publication step.

The already accepted five-second safety continuation may acknowledge
`rollback-pending` after the forward context expires. It may not select code,
remove a retained payload, call an Adapter, or continue rollback. If the caller,
authenticated, or local self-test deadline is expired after the forward failure,
`Apply` durably appends state 10 under that continuation and returns. Only a
later explicit identical `Apply` with a live caller context may continue the
rollback episode from state 10. This prevents cancellation from becoming
authority for an unbounded post-cancellation activation.

For D3-D10, an identical transaction has the same update root, transaction
generation, candidate artifact bytes and manifest commitment, schema plan,
forward `Decision`, and caller-owned Adapter identities required by the
accepted Interface. Caller context and `RollbackDecision` are deliberately not
part of that identity: every public invocation supplies a fresh live context
and a freshly evaluated retained-payload decision. The fresh decision must pass
all D2 equality and non-extension predicates; it cannot change the candidate,
forward authorization, or journal identity.

An explicit identical `Apply` after durable network unavailability receives a
fresh local 15-second window but cannot extend either authenticated deadline or
that invocation's caller deadline. This is the sole journal-v1 exception to
the earlier non-extension rule: a retry terminal entry may have a later local
deadline than the unavailable `self-testing` entry, but never a later
authenticated bound. Its elapsed observation is the previous journal elapsed
value plus the new invocation's monotonic delta, so the chain remains
non-decreasing across processes without treating the old value as a clock.

### D4 — exact self-test classification and retry

The self-test Adapter is responsible for checking the exact copied
`CandidateIdentity` plus its closed-over trusted environment/root, activation
generation, schema readability, Vault commitment, release floors, local IPC
readiness without an ambient listener, and capability-specific offline/online
predicates. Update Transaction proves the bounded identity supplied, exact call
count/deadline, error classification, state publication, and D0 non-mutation;
it does not pretend to implement those foreign predicates itself.

| Self-test observation | Durable action | Public continuation |
|---|---|---|
| nil from complete offline-capable or online success | append state 8 with `adapter-success`, then the unchanged V0 state 9 with `adapter-not-called` | `committed` |
| unavailable-only tree | append state 8 with `adapter-unavailable`; leave candidate selected and networking stopped | return bounded unavailable result |
| unavailable plus any other leaf or local failure while the effective context remains live | append state 8 with `adapter-failed`, then state 10 `rollback-pending` | continue directly into D6 rollback |
| self-test deadline or caller cancellation | append state 8 with `adapter-failed`, then acknowledge state 10 under the safety continuation | return at `rollback-pending`; a later explicit identical Apply may continue D6 |

An explicit identical `Apply` may resume a coherent state-8
`adapter-unavailable` transaction. It reacquires and completely reinspects the
root, matches the same transaction generation, candidate artifact and manifest,
forward Decision, and physical successor selection, then calls only self-test.
It does **not** repeat staging, `StopNewWork`, `Drain`, generation publication,
or activation.

- unavailable again returns the same bounded state with the new original error
  and writes no entry; the new process-local observation/deadline is discarded,
  and a later retry recomputes both from its own invocation;
- success appends state 9 `committed` with `adapter-success`, proving that the
  retry — rather than the earlier unavailable call — succeeded;
- a non-unavailable failure appends state 10 `rollback-pending` with
  `adapter-failed` and continues to rollback.

A crash before the retry terminal entry leaves the original unavailable prefix
and is safely retryable. A state-8 `adapter-success` crash resumes by appending
the unchanged state-9 `adapter-not-called` without calling self-test again.
There is no second state-8 entry and no overwrite. Original V0 uses the first
success path, so all of its entry bytes and predecessor commitments remain
byte-exact.

When a retry does append a terminal entry, its elapsed value is the last durable
elapsed value plus only that invocation's captured monotonic delta. Its deadline
is the D3 minimum computed for that invocation. A no-write unavailable retry
changes neither durable field.

### D5 — S7.2-05a outcome and Result table

All rows have the transaction generation, no staging, and custody read from the
physically selected current manifest. Zero digests below mean the exact
zero-value arrays, not omitted evidence.

| Observation | `Outcome/State` | Error | Current / rollback digest | Fixed safe notice |
|---|---|---|---|---|
| complete offline-capable success | `committed/committed` | nil | candidate / predecessor | `update committed` |
| complete online success | `committed/committed` | nil | candidate / predecessor | `update committed` |
| normative online check unavailable; all reported leaves unavailable | `application-networking-unverified/self-testing` | non-nil original tree | candidate / predecessor | `update networking unverified` |
| network unavailable plus local failure while context remains live | continue through state 10 and D6 | original joined tree retained | determined by D6 | determined by D6 |
| local predicate failure while context remains live | continue through state 10 and D6 | original error retained | determined by D6 | determined by D6 |
| self-test deadline or caller cancellation | `self-test-failed/rollback-pending` | deadline/cancellation retained | candidate / predecessor | `update self-test failed` |
| cleanup fails or its five-second continuation expires | `cleanup-incomplete/<last coherent state>` | non-nil | zero / zero | `update cleanup incomplete` |
| evidence is corrupt, contradictory, or ambiguous | `transaction-invalid/transaction-invalid` | non-nil | zero / zero | `update transaction invalid` |

The unavailable result is nonterminal and intentionally retryable only by an
explicit identical caller request. It never claims commit, marks the payload
bad, changes its authenticated safety status, lowers a floor, calls rollback,
or reopens normal networking.

### D6 — exact rollback policy and journal transitions

A non-network forward failure durably appends `rollback-pending` before any
rollback predicate or selection change. Under the same owned-root lock, Apply
then evaluates D2. There is no execution merely because retained bytes exist.
If the effective operation context is no longer live, Apply returns the D5
`rollback-pending` result instead; a later explicit identical Apply must
reinspect every D2 predicate before continuing.

When admitted, rollback performs this exact order:

1. encode the predecessor-current/rollback-absent record into one exact direct
   regular sibling temp; write it completely, flush the file, atomically replace
   `current`, and acknowledge the containing directory using the accepted
   platform durability primitive;
2. reopen `current` without following a link, bounded-read it, and verify its
   complete bytes, regular-file identity, predecessor tuple, rollback absence,
   and transaction generation before treating the replacement as selected;
3. remove only the now-unselected failed candidate generation under the shared
   five-second cleanup continuation and acknowledge its parent;
4. call the same injected `SelfTest` with a bounded identity reconstructed from
   the independently verified retained manifest, under D3's rollback deadline;
5. on success append `rolled-back`; on failure append `repair-required`.

Failure or expiry while appending state 10 under the safety continuation is
resolved by a complete locked reinspection. If no canonical state-10 entry is
durable, return `cleanup-incomplete/self-testing`; recovery sees R17 and may
continue only on a later explicit `Apply`. If a complete coherent state-10 entry
is durable, return `cleanup-incomplete/rollback-pending`; recovery sees R18.
Neither result guesses from the write error or continues selection work.

Rollback changes code selection only. It does not roll back or copy mutable
schema, Authority, release roots/floors, Network Epoch, Namespace, freshness,
generation, exposure, credentials, Grants, or signing state. The work-control
Adapter is not called again and normal networking remains stopped throughout
this transaction. A later runtime start is outside this Module operation.

If D2 refuses the retained payload, Apply never selects or self-tests it. It
appends `repair-required` with the refusal classification while preserving the
failed candidate as current and the verified predecessor as rollback. This
preserves both exact evidence sets for bounded offline inspection; the terminal
state, not executable presence, prevents normal networking.

If predecessor selection has been durably published but retained start fails,
the exact physical selection is **predecessor current, rollback absent, failed
candidate removed, networking stopped, state `repair-required`**. Restoring the
known-failed forward candidate would manufacture a second unsafe activation;
retaining it as rollback would advertise a failed payload as the safe fallback.
The predecessor is therefore the only selected code, but no journal entry or
Result claims it started successfully.

### D7 — S7.2-05b outcome and Result table

Within the invocation that observed it, every ordinary row retains the original
forward `SelfTest.Check` error in the returned error tree. A later explicit
continuation or `Recover` cannot reconstruct that process-local tree and returns
the stable durable terminal error named by the row instead. Rollback-start
failure additionally retains the exact rollback-check error when observed in
the same invocation. Stable bounded notices never contain dynamic strings.

| Forward/rollback observation | `Outcome/State` | Error | Current / rollback digest | Fixed safe notice |
|---|---|---|---|---|
| forward local failure; all D2 predicates pass; predecessor selection and retained self-test succeed | `rolled-back/rolled-back` | non-nil original forward error | predecessor / zero | `update rolled back` |
| rollback revoked, digest-mismatched, schema-incompatible, below a floor, expired, or otherwise rejected by D2 | `rollback-refused/repair-required` | non-nil joined forward + stable refusal | failed candidate / predecessor | `update rollback refused` |
| rollback current replacement is uncertain and cannot be normalized | `transaction-invalid/transaction-invalid` | non-nil | zero / zero | `update transaction invalid` |
| predecessor selection succeeds but retained self-test fails, expires, is cancelled, or is unavailable | `repair-required/repair-required` | non-nil joined forward + rollback error | predecessor / zero | `update repair required` |
| abort/removal/publication cleanup fails or overruns | `cleanup-incomplete/<last coherent state>` | non-nil | zero / zero | `update cleanup incomplete` |

`rolled-back` is a handled safety terminal but still returns a non-nil error so
the caller cannot mistake a failed update for commit. The observing Apply joins
the original Adapter evidence with the stable rolled-back error; a later Apply
or `Recover` returns that stable non-nil error alone. The outcome, state, Result
fields, and error nil/non-nil classification therefore do not change across a
restart.

### D8 — exact physical selection table

| Durable condition | `current` record | Payload directories | Staging | Normal networking |
|---|---|---|---|---|
| committed, including unavailable retry success | candidate current; predecessor rollback | both immutable generations | absent | may be started by the runtime owner |
| self-testing unavailable | candidate current; predecessor rollback | both immutable generations | absent | stopped |
| rollback-pending before rollback publication | candidate current; predecessor rollback | both immutable generations | absent | stopped |
| rollback refused | candidate current; predecessor rollback | both immutable generations | absent | stopped by `repair-required` |
| rollback replacement published, terminal not yet acknowledged | predecessor current; rollback absent | predecessor plus declared failed-candidate residue until bounded cleanup | absent | stopped |
| rolled-back | predecessor current; rollback absent | predecessor only; failed candidate absent | absent | remains stopped during this operation |
| rollback start failure / repair-required | predecessor current; rollback absent | predecessor only; failed candidate absent | absent | stopped |

No row creates a second staging payload, a third retained payload, an in-place
artifact mutation, or an undeclared repair tree. External Owner mutation is
detected on the next inspection; prevention is not claimed.

The failed forward candidate occupies the transaction's sole cleanup/residue
slot until it is either removed or preserved by a terminal refusal. At every
observable point there are at most two payload generations, no staging payload,
one `current` record, one permanent lock, one transaction journal of at most 16
entries, and at most one declared direct regular `current` replacement temp.
Admission of a third payload generation, second replacement temp, second
journal, unknown directory, link/reparse object, aliased object, missing selected
generation, or contradictory selection is `transaction-invalid` before an
Adapter call or mutation.

### D9 — append-only journal-v1 amendment

Keep the 139-byte record, all field offsets, record version, adapter-result
codes, and codes 1-9 unchanged. Add only these state codes and canonical names:

| Code | State | File |
|---:|---|---|
| 10 | `rollback-pending` | `10-rollback-pending.entry` |
| 11 | `rolled-back` | `11-rolled-back.entry` |
| 12 | `repair-required` | `12-repair-required.entry` |

The maximum of 16 entries is unchanged. Codes 10-12 use the same generation,
candidate digest/manifest commitment, predecessor-entry commitment,
non-decreasing observation, and deadline fields. The candidate commitments
identify the failed forward transaction even when predecessor code becomes
current.

Permitted terminal chains are exactly:

```text
1..8(adapter-success), 9(adapter-not-called)             # V0
1..8(adapter-unavailable), 9(adapter-success)             # explicit retry
1..8(adapter-failed), 10(adapter-not-called), 11(success) # safe rollback
1..8(adapter-failed), 10(adapter-not-called), 12(adapter-not-called) # refused
1..8(adapter-failed), 10(adapter-not-called), 12(failed)  # start failure
1..8(adapter-unavailable), 10(adapter-failed), 11(adapter-success)
1..8(adapter-unavailable), 10(adapter-failed), 12(adapter-not-called|adapter-failed)
```

In the last line the retry's non-unavailable forward failure is proved by code
10 `adapter-failed`; subsequent code 11/12 follows the same rollback rules.
Code 12 `adapter-not-called` means rollback predicates refused before the
retained Adapter call. Code 12 `adapter-failed` means retained start failed.
Other adapter/state combinations, duplicate states, a code after 9/11/12, or a
gap are invalid. State 11 uses `adapter-success`. V0 code 9 remains
`adapter-not-called`; only success after durable unavailable uses code 9
`adapter-success`.

### D10 — literal R15-R24 recovery extension

R00-R14 remain byte-for-byte and behaviorally unchanged. R13 specifically means
a canonical state-8 `adapter-success` journal prefix with coherent successor
current/predecessor rollback selection and state 9 absent; recovery appends only
the unchanged V0 state-9 `adapter-not-called`. R14 means the complete V0 code-9
`adapter-not-called` terminal. Every new row has the permanent direct regular
single-link lock and a canonical predecessor chain.

| ID | Last complete journal prefix | Physical state on entry | Required Result and normalization |
|---|---|---|---|
| R15 | state 8 `adapter-unavailable` | successor candidate current, predecessor rollback, no staging | preserve; return `application-networking-unverified/self-testing`, candidate/predecessor digests, non-nil `SelfTestUnavailable{}` |
| R16 | state 9 `adapter-success` after R15 | same coherent successor selection | return committed terminal facts and nil; V0 public Result bytes are unchanged |
| R17 | state 8 `adapter-failed`, no state 10 | same successor selection | preserve; return `recovered/self-testing`, nil; an identical Apply may append state 10 without rerunning the failed forward test |
| R18 | state 10 `rollback-pending` | successor candidate current, predecessor rollback | preserve; return `recovered/rollback-pending`, nil |
| R19 | state 10 | R18 plus one exact complete direct regular predecessor-current sibling temp, before replacement | remove only the exact temp and return normalized R18 |
| R20 | state 10 | predecessor current with rollback absent; failed candidate is one exact unselected generation | remove only that exact failed candidate under bounded cleanup; return normalized R21 |
| R21 | state 10 | predecessor current, rollback absent, failed candidate absent | preserve; return `recovered/rollback-pending`, predecessor/zero digests, nil |
| R22 | state 11 `adapter-success` | predecessor current, rollback absent, failed candidate absent | return `rolled-back/rolled-back`, predecessor/zero digests, non-nil stable rolled-back error and `update rolled back` |
| R23 | state 12 `adapter-not-called` | failed candidate current, predecessor rollback | return `rollback-refused/repair-required`, candidate/predecessor digests, non-nil stable refusal error and `update rollback refused` |
| R24 | state 12 `adapter-failed` | predecessor current, rollback absent, failed candidate absent | return `repair-required/repair-required`, predecessor/zero digests, non-nil stable repair error and `update repair required` |

R18 also covers a rollback current replacement that crashed and resolved to the
complete old successor record. R20 covers replacement that resolved to the
complete predecessor record, including successful replacement durability with
no terminal entry. A partial, mixed, missing, aliased, or third selection is
`transaction-invalid`; recovery never guesses which executable ran.

R20 cleanup follows the accepted five-second continuation: check immediately
before each remove/sync, start no later operation after expiry, observe an
in-flight overrun, and return `cleanup-incomplete/rollback-pending` with zero
physical Result fields on any failure. It never removes the predecessor,
permanent lock, transaction journal, or an object that does not match the exact
failed candidate commitments.

R19 is a current-record publication interruption: it removes only the exact
direct sibling temp after proving that the old complete successor record remains
selected. This is intentionally different from S7.2-02 R08, which moves an
exact declared staging payload to the aborted-evidence location. D6 never moves
a payload to `aborted`, and R08 never normalizes a `current` replacement temp.

`Recover` calls no `SelfTest` and never automatically continues rollback. An
explicit identical `Apply` may continue R15, R17, R18, or R21 under the rules
above without repeating stop/drain/forward activation. Terminal R22-R24 are
idempotent and write nothing.

## Independent red oracle

Tests cross public `Apply` and `Recover` except for the already accepted private
per-invocation interruption/filesystem-operation seams. No package-global
mutable fault, context value, exported test hook, generic filesystem mock,
network call, or production encoder is allowed.

The independent oracle must cover at least:

1. V0 exact journal bytes, Result JSON, Adapter counts, and D0 snapshots;
2. offline success, online success, unavailable-only, unavailable joined with
   a local leaf, deadline, and cancellation;
3. original error-tree preservation using identity-comparable test leaves;
4. unavailable repeated once with no write, then explicit success with code 9
   `adapter-success` and zero additional stop/drain/activation calls;
5. rollback valid, revoked, digest mismatch, schema incompatible, below-floor,
   replacement uncertainty, and retained start failure;
6. exact selection and residue for every D8 row;
7. literal independent journal bytes for codes 10-12 and every R15-R24 row;
8. crash before/after rollback temp publication, atomic replacement, candidate
   removal, retained self-test, and terminal entry publication;
9. cleanup failure/overrun with exact completed-plan prefix and no later step;
10. unchanged Vault, Authority, release floors, Network Epoch, Namespace,
    freshness, generation, exposure, credentials, Grants, handles, goroutines,
    and timers.

Expected classifications, digests, records, and Results are literal or encoded
by test-only code from frozen fixture facts. They do not call production
classifiers, encoders, inspectors, hash helpers, result constructors, or the
candidate's own summary.
