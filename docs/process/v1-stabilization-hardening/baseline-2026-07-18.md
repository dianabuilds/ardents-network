# Ardents V1 Reproducible Baseline — 2026-07-18

## Scope

This report is the evidence artifact for `STB-001`. It records the first
reproducible state of the root `v1` implementation before stabilization work.
Red results are intentionally retained: the baseline gate requires every red
signal to be reproducible and classified, not prematurely repaired.

Captured on Windows/amd64 with Go `1.26.1`; `go.mod` declares Go `1.26.0` and
toolchain `go1.26.1`. The principal network dependencies are libp2p `v0.48.0`
and go-waku `v0.10.1`.

## Execution Normalization

The workspace contains an empty `.git` directory, so Go VCS stamping fails
with exit status 128. The managed system Go cache is also not writable. The
canonical runs below therefore used the workspace cache and disabled VCS
stamping:

```powershell
$env:GOCACHE=(Resolve-Path '.gocache').Path
$env:GOFLAGS='-buildvcs=false'
```

This changes build metadata only; it does not replace or bypass product
behavior.

## Classified Findings

### Product and security

- `BL-001`: the tagged network-foundation suite does not compile because its
  fixtures use `*transport.Service`, a pointer to an interface. This is test/API
  drift and is assigned to `STB-002`.
- `BL-002`: the workload observed-exit E2E scenario fails when looking up its
  Windows process marker. Product-versus-harness ownership remains to be
  isolated by `STB-003`.
- `BL-003`: the test catalog binds
  `TestDiscoveryStatusCountsExpiredRecordAsStaleAndRejected` to `DKI-002` in
  code and `DII-001` in the scenario document. This metadata drift is assigned
  to `STB-004`.
- `BL-004`: vulnerability truth has drifted materially from
  `docs/security-exceptions.md`. There are 11 reachable findings, including Go
  TLS/X.509/net issues, quic-go `0.59.0`, x/net HTTP/2, and pion/dtls/v2. The
  dependency and exception decision belongs to Phase 1.
- `BL-005`: Waku runtime logs expose readable product topic names such as
  `ardents/1/blob-request` and `ardents/1/discovery-record`. This confirms the
  documented privacy blocker assigned to Phase 2.

### Test harness and evidence production

- `BL-006`: `tests/run.ps1` does not reliably propagate the exit status of its
  `go test` child, allowing a failed fast run to return success.
- `BL-007`: the same runner can return success after VCS/cache failures and a
  missing-report warning.
- `BL-008`: on integration build failure and E2E test failure the canonical
  summary and JUnit evidence are absent, leaving only raw per-test E2E JSON.
  Runner behavior is assigned to `STB-004`.
- `BL-009`: the CLI JSON watch test can exceed its deadline under full-suite
  load while passing ten focused repetitions. It remains a stability signal for
  `STB-005`, not evidence that the command is functionally broken.

### Environment

- `BL-010`: the empty `.git` directory and inaccessible managed Go cache require
  the normalization above. These are workspace constraints and must remain
  explicit in every retained local report.

## Vulnerability Snapshot

Reachable findings observed by `govulncheck`:

- Go standard library: `GO-2026-5856`, `GO-2026-5039`, `GO-2026-5037`,
  `GO-2026-4971`, `GO-2026-4947`, `GO-2026-4946`, `GO-2026-4918`,
  `GO-2026-4870`, and `GO-2026-4866`;
- quic-go: `GO-2026-5676`, fixed in `v0.59.1`;
- pion/dtls/v2: `GO-2026-4479`, with no fixed version reported.

The toolchain findings require at least Go `1.26.5` for the complete reported
standard-library fix set. This report records the evidence but does not approve
an upgrade; dependency safety and compatibility checks are Phase 1 work.

## Baseline Conclusion

`STB-001` is complete. The baseline is not green, but every observed red signal
has a repeatable command, an ownership classification, and a destination task.
The next executable task is `STB-002`.
