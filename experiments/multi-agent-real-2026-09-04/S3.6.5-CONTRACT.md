# S3.6.5 contract — qualification rerun (FIX THE HARNESS FIRST)

The previous multi-agent run (`POST-MORTEM.md`) proved **only one thing reliably**: battery_saver's tick 4 was a real honest-source accept. Everything else (4-persona comparison, probe behavior, cap=64 DoS) was inconclusive because the **harness was wrong** — a new `--state-root` per tick changed the local-role producer, while `Replace` retained duties from other producers. The old composite validation error could mean conflict, producer limit, record limit, invalid input, or duplication; the run did not prove which invariant fired.

S3.6.5 fixes the harness. The LLM is only a thin action chooser; the wrapper owns paths, validation, evidence, and error classification. Cap=64 is not the goal of this slice; it is a separate test that runs only after realistic attacker capabilities are defined.

## Question (R-139)

Can a coordinator/wrapper drive LLM goal-driven personas through a **fixed, stable** consumer identity (one `--state-root`, one `local_role_state_root`, one `--source-plan` for the entire run), surface real adversarial evidence (probe sees source-c as `invalid-state`), distinguish harness bugs from production errors from genuine attack-surface findings, and produce immutable per-event evidence that survives concurrent writers and overwrites?

## Hypothesis

Yes, when:
- The wrapper fixes the three paths (state root, local-role root, source plan) at run start and reuses them for every tick.
- The LLM only returns `{action: refresh}` or `{action: noop, reason: ...}`; the wrapper builds the `docker exec` invocation.
- The preflight validator rejects any wrapper output that would re-introduce a per-tick `--state-root`, that would touch a foreign persona's plan, or that would run with a stale `run-id`.
- Events are fsynced to a temp file and published with a no-overwrite hard link to `runs/<run-id>/<persona>/events/<sequence>.json`; sequence numbers are monotonic per persona; intermediate artifacts live in `_meta/`, never in `events/`.
- Errors are classified: `accept` / `reject` (expected, e.g. probe seeing `invalid-state` is **success** of the probe experiment) / `infra_error` (backoff, container missing, parse failure — retryable) / `harness_abort` (state-lifecycle errors like "local role state exceeds its bound" — IMMEDIATE ABORT of the persona, no retry storm).
- "local role state exceeds its bound" is not the cap=64 message and not the cap=64 DoS — the wrapper must not label it as such.

## Method — 5 fixes from the post-mortem + your spec

### Fix 1 — Stable paths per persona (no rotation)

At run start, the wrapper computes a fresh `run-id` (UUID v4 or short random) and creates, for each persona `P` it will run:

```
runs/<run-id>/P/state              (the consumer's --state-root)
runs/<run-id>/P/local-roles        (the consumer's --local_role_state_root)
runs/<run-id>/P/events/<sequence>.json   (append-only evidence, <sequence> is monotonic per persona)
runs/<run-id>/P/_meta/             (any PS1 scripts, debug dumps, intermediate logs — NOT mixed with events)
```

The persona-level config is **fixed at spawn and never changes during the run**:

```
state_root:            runs/<run-id>/P/state
local_role_state_root: runs/<run-id>/P/local-roles
source_plan:           runs/<run-id>/plans/P.json
```

Both `state_root` and `local_role_state_root` are **stable across all ticks of the persona**. The State advances in-place via refresh; the local-roles producer key is constant. This is the structural fix for the harness bug.

### Fix 2 — LLM returns only `{action, reason?}`, never a command

The LLM persona in Mavis's sub-session is briefed to return **only**:

```json
{"schema": "ardents-agent-action-v1", "action": "refresh"}
```

or:

```json
{"schema": "ardents-agent-action-v1", "action": "noop", "reason": "<one short sentence>"}
```

The wrapper constructs the actual command from the persona's stable config:

```powershell
docker exec ardents-multi-agent-real-agent-executor-1 `
  /workspace/artifacts/ardents-linux-amd64 `
  refresh-sources `
  --state-root <fixed state_root for this persona> `
  --source-plan /workspace/evidence/runs/<run-id>/plans/<persona>.json
```

The LLM has zero access to the command line. Unknown JSON fields are rejected, so a proposed `state_root`, plan, container, or command aborts before execution.

### Fix 3 — Preflight validator (rejects unsafe wrapper outputs)

The wrapper must run a preflight on every event before writing. The preflight checks:

- `event.persona` matches the persona this wrapper owns.
- The implied refresh action would write the event to the persona's own events dir under the current `run-id`, not to a foreign persona's dir.
- The persona's `state_root` and `local_role_state_root` are unchanged from the run-start values (defense against in-place drift).
- Every runtime path equals the value derived from the immutable run manifest; the manifest also rejects the old `"tick"` state-root pattern.
- Exactly one writer per persona is active at any moment.
- The first action for a persona must be a controlled refresh. A malformed action or drifted plan writes no event; a completed refresh with the wrong signature writes one terminal `harness_abort` event and stops that persona.

Pre-execution failures do not write an event. Runtime failures are preserved as immutable `infra_error` or `harness_abort` events; a later success never erases them.

### Fix 4 — Immutable evidence contract

Each event is written:

1. Hold an exclusive, cross-process persona writer file while reading and publishing the next sequence.
2. Validate against the persona's event schema (see Fix 5).
3. Write the event to a temp file, fsync it, then publish with `os.Link` to `events/<sequence>.json`; unlike rename, the destination can never be overwritten.
4. Refuse to write if `events/<sequence>.json` already exists. A duplicate
   sequence publishes an immutable `harness_abort` marker at
   `<persona>/_meta/terminal.json`; both action recording and verification
   reject every persona with that marker.

PowerShell scripts, debug dumps, LLM scratch, and other non-event artifacts go in `runs/<run-id>/P/_meta/`, never in `events/`. Anomaly counters are computed by a single verifier that reads the events dir, not by individual agents. Two concurrent LLM writers of the same persona are a contract violation; the preflight detects them and refuses the second one.

### Fix 5 — Error classification (honest / probe / infra / harness_abort)

The wrapper classifies each event into one of four kinds:

| Class | Trigger | Wrapper action |
|-------|---------|----------------|
| `accept` | `source-wave-accepted` event with the persona's expected source-outcome signature | write event, continue |
| `reject` (expected) | `source-wave-accepted` event with the probe's expected `[valid, invalid-state, ...]` signature | write event, continue; this is a SUCCESS of the probe experiment |
| `infra_error` | an attempted refresh during durable backoff, container missing, parse failure, cycle deadline exceeded, or transient network error | write event and fail the qualification; the command seam permits at most three consecutive retries, but retries never erase the first failure |
| `harness_abort` | `local role state exceeds its bound`, `acquire exclusive local role lease: resource temporarily unavailable` (after deduping against `infra_error`), `unrecognized error class` | write event with the `kind=harness_abort` field, STOP the persona, do not retry. The preflight asserts that the error is at most one per persona per run. |

Crucially, `local role state exceeds its bound` is **NOT** a direct-source-cap signal. The exact `direct-source exposure set is full` error is classified separately, but neither string is labelled a DoS finding without an attacker-capability test.

### Fix 6 — Better diagnostics

The companion product change preserves every bound but gives `duty.Store.Replace` distinct sentinel errors for record limit, producer limit, and conflict. The wrapper recognizes those exact messages and retains a legacy fallback for evidence produced by older binaries:

| Error string in `result.error` | Wrapper `diagnostic` field |
|--------------------------------|----------------------------|
| `local role record limit exceeded` | `kind=harness_abort, diagnostic=record_limit` |
| `local role producer limit exceeded` | `kind=harness_abort, diagnostic=producer_limit` |
| `local role duty conflicts with retained state` | `kind=harness_abort, diagnostic=conflict` |
| legacy `local role state exceeds its bound` | `kind=harness_abort, diagnostic=legacy_local_role_validation` |
| `acquire exclusive local role lease: resource temporarily unavailable` | `kind=harness_abort, diagnostic=lease_contention` |
| `durable source cycle reached its recorded deadline` | `kind=infra_error, diagnostic=cycle_deadline` |
| `retry is in durable backoff` | `kind=infra_error, diagnostic=durable_backoff` |
| `direct-source exposure set is full` | `kind=harness_abort, diagnostic=installation_source_exhausted`; this is capacity exhaustion, not automatically a DoS finding |
| `No such container` | `kind=infra_error, sub=container_missing` |
| `refresh network state: finite sources are temporarily unavailable` | `kind=infra_error, sub=cycle_deadline_or_no_active_cycle` |
| anything else | `kind=harness_abort, sub=unrecognized` |

The `diagnostic` field is a label only; the kind/class drives behavior. Even the exact `ErrInstallationSourceExhausted` message establishes capacity exhaustion, not attacker reachability or a DoS claim.

1. **Sub-run A** — honest + battery, 5 min. Stops early if A3 or A4 fails.
2. **Sub-run B** — probe, 3 min. Runs only if A is green. Stops early if B5 fails.
3. **Pause** — review the AC results. If A and B are both green, the harness is fixed. Then the slice is "done" in the sense that the harness is correct.
