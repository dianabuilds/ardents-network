# Local Application Execution

Local authority/session rules, installed launch composition and fixed native
worker mechanisms have separate owners. `execution` owns volatile Local Grants,
one-use capabilities, Session current/last Job, one lifetime claim and one
operation claim that never becomes reusable.
`Supervisor` retains a distinct physical cleanup slot after revoked admission;
failed cleanup retains that slot and the first terminal generation failure.

`runtime` consumes exact local authority, serializes the shared fixed activation
inventory and retains ambiguous activation obligations. It pins original cleanup
before destination-free Text INIT and rechecks original artifact/invocation after
READY before constructing a fresh private byte Grant. Empty preparation joins
that Grant and worker before returning a distinct completed-current provenance.
That provenance grants no live worker operation. Failed original cleanup retains
the shared activation gate, so a different owner cannot consume its baseline.
After a qualified handoff, a live invocation releases activation serialization
while retaining its original cleanup pin. Its sealed Operation checks the exact
Job, byte lease and original caller. Retirement interrupts before waiting for
the operation's own borrowers, then joins original worker cleanup. A borrowed
physical close failure closes the generation synchronously; later nil outcomes
cannot erase it or accept a late sibling result.
The bounded setup/Control invocation owns the sole post-READY attachment
reader. EOF, credential/descriptor refusal or unsolicited bytes retires its
exact Job and interrupts borrowers. Joined invocation acceptance also requires
that observation to succeed. A worker-use failure remains distinct from a
physical cleanup failure: clean original cleanup permits another launch while
the failed invocation permanently refuses completed-current provenance.
The pinned cleanup owner reports its first definite physical failure directly
to the exact launch Job before continuing descendant observation. The generation
therefore denies sibling effects while join remains pending; this report returns
no cleanup capacity. A missing manager remains a provisional observation until
original pinned removal or a retained failure is established.
A future Text consumer must own its protocol reader instead of sharing this
setup reader.

Command and lifetime composition use the same portable implementation. The
native worker adapter remains separate: unsupported platforms return no
activation, artifact or cleanup pin. The common owner joins the original refused
local Job and returns its slot before another attempt; no participant console,
durable Network/Stock/Hosting root or Route work can precede qualified launch.
Only the Linux initialization seam borrows destination-free Text INIT. Portable
composition and its refusal checks establish no Windows worker support.

`worker` owns fixed installed artifacts, typed manager inventory/properties,
per-read credentials and SCM_RIGHTS closure, pinned cgroup events and original
stop/join. Its factory selects only the fixed Text artifact and admitted local
surface; it exposes no Qualification inventory, Endpoint-wide cgroup pin or
unconsumed artifact/attachment getters. Internal manager and file observations
remain private mechanisms. Ordinary Execution admits Ubuntu24/systemd255 only. Installation's
separate native admission is unchanged. A failed Stop retains its error while
continuing original descendant observation; path absence/MainPID0/timeout alone
never proves join. Fixed helpers retain their creating thread through actual
child join with parent-death termination.

Pinned socket files do not attest the manager's loaded socket. Before dial and
at original invocation observation (including the post-READY check), the worker
checks actual typed Unit/Socket facts against the existing pure fixed-unit
contract. Only detached typed values and expected socket protection cross that
mechanism boundary; no Installation admission, lease or start authority is lent.

The new consumers are `ardents-next execution prepare-permission` and
`ardents-next execution route-holder`.
It retains the permission holder while its finite console obtains a real signed
response and drives new Network/Admission/Hosting/Route bootstrap operations.
Preparation checks surround signed currentness and final local handoff. The
live holder retains one qualified operation through genuine Route setup and
Control, joins Route/Stock/Network borrowers, closes the operation and original
invocation, then checks the exact completed-current result. It refuses private
publication and JOIN/Service operations. Neither command establishes accepting
installed Endpoint startup or an authenticated Service Connection.
Private Publication/Connection, Instance readiness, full installed lifecycle,
qualification and complete domain acceptance remain separate dependencies.

The separately root-pinned hostile-tree component exercises this same new
runtime on both local surfaces. Independent kernel event and original
proc-directory observations require actual TERM-ignoring child/grandchild
lineage, original-tree join and survival of the other surface's sibling
invocation and operation. Attachment loss refuses effects before operation
join; original failed-use completion cannot become successful provenance.
The ordinary artifact's absent descendants are a failing environment control.
The fixture authorizes the local owner; no Service, logical recovery or escape
qualification follows. Its driver and limits belong to the
[Execution tree profile](../../../tests/qualification/execution-tree/README.md).

The separate [Execution escape profile](../../../tests/qualification/execution-escape/README.md)
uses the separately root-pinned adversarial Text artifact through this runtime.
Independent host listeners require positive controls before launch and after
original worker join on both local surfaces; any other contact fails. Original
kernel event/proc descriptors observe cleanup, while retired operations refuse
effects. This bounded component establishes no private Service, logical recovery,
independent security or whole-host qualification.

The separate [Endpoint-death profile](../../../tests/qualification/execution-recovery/README.md)
runs its Root observer outside a held qualification Endpoint. Actual pidfd
SIGKILL interrupts an original Endpoint that has genuine qualified operations
on both local surfaces. Original kernel/proc descriptors require its scope
and both hostile descendant trees to disappear without Endpoint Go cleanup or
Root worker Stop. The original failed signal result is retained. Explicit
fresh start requires fresh Endpoint/worker invocations, volatile local generation
and Job commitments before repeating that observation. It is local physical
lifetime evidence, not private Service continuity or installed-product acceptance.
