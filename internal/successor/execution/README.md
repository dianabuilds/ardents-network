# Local Application Execution — каркас

Только описание будущего владельца; Go-пакета и реализации здесь пока нет.

**Вопрос домена:** может ли этот конкретный запуск Application выполнить операцию?

**Входит:** поколение Local Grant, локальная сессия с точным текущим/последним
Job и однократной передачей результата; отдельный supervisor с конечной
ёмкостью очистки и сохранённой терминальной ошибкой; проверенный запуск worker.
Job — сущность сессии, а не отдельный домен. Правила, supervisor и системный
механизм запуска имеют разные обязанности; один общий агрегат не предполагается.

**Не входит:** выбор Target/Route, токены, публикация Service, восстановление
Connection, установка ПО, общепроцессное давление ресурсов и текстовая семантика.

**Состояние и завершение:** отзыв синхронно запрещает новые эффекты, прерывает
зависимую работу, дожидается исходного дерева worker и лишь затем возвращает
ёмкость очистки. Поздний результат не получает права нового поколения.

**Соседи:** Software acceptance предоставляет точный разрешённый артефакт;
Publication и Connection удерживают исходную операцию и проверяют её перед
эффектами и передачей результата. Они не изменяют Job и завершают свои ресурсы.

**Где искать обязанности:** `internal/application/broker`, Job и worker в
`internal/endpoint`, проверки эффектов и передачи результата в Service.
Это источники для разбора, не разрешённые импорты.
