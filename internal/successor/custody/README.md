# Authority Custody — каркас

Только описание будущего владельца; Go-пакета и реализации здесь пока нет.

**Вопрос домена:** как хранить корневые полномочия и использовать их по назначению?

**Входит:** зашифрованное хранение, разблокирование, точные одобренные обязательства
подписи, долговечные ограничения восстановления и стирание секретов.
Разные виды authority сохраняют отдельные права и историю.

**Не входит:** универсальный Sign, экспорт приватного корня, принятие State,
распределение Admission, правила Release и готовность Service. Runtime-ключи
Instance и Node не становятся корневыми полномочиями Custody.

**Состояние и завершение:** секреты принадлежат своему назначению; долговечный
переход фиксируется до ответа. Отзыв/закрытие завершает сессию и стирает
приватный материал; восстановление не сбрасывает прежние floors.

**Соседи:** соответствующий домен задаёт точное одобренное назначение, Custody
выполняет допустимое использование ключа. Admission сохраняет правила allocation;
выдача Service Credential сохраняет собственную политику одобрения и поколения.
Ни сосед, ни общая композиция не получают приватный корень.

**Где искать обязанности:** `internal/custody`, purpose-specific операции подписи
и подготовки в текущих командах. Удалённые Name-полномочия не восстанавливаются.
