# Source artifact admission and bounded initial installation

This supporting Software acceptance owner implements ADR-0123's Source
artifact component, read-only native preflight, initial stopped transition and
guarded first startup. `artifact.go` owns canonical descriptor preparation and exact
public program/template agreement. `admission.go` owns one coherent pair of fresh
Release authorizations, the immutable handoff and retained original loader caller.
It imports Enrollment and Release, never Endpoint Installation. `source_plan_linux.go` consumes Source's pure serving-declaration codec and finite runtime credential-pair validation, also used by the runtime owner; Installation owns exact future-input matching, explicit delivery and preflight admission. No runtime is constructed.
`source_request_linux.go` owns a separate closed Source request and exact unit
template/rendering. `source_observation_linux.go` retains original root-controlled
request/plan/certificate/private-key/CA files and ancestors through joined Close.
It consumes only the narrow fixed Source read-only systemd connection; this does
not generalize Endpoint policy or grant manager mutation methods.

The canonical `ardents-source-preflight-v1` request separates existing input
sources from four absent future destinations: installation, State, participation
and credential directory. It binds the existing Source plan's future credential
names, literal unprivileged TCP address and exact process profile. Native checks
observe Ubuntu24.04/systemd255, cgroup-v2, ext4 destination ancestors, local NSS
and fresh fixed account/unit namespace. Root-owned 0644 live clock access is
reobserved without freezing inode, mtime or contents; State retains time policy.
The clock writer is root in this bounded request. Original manager Version and
UnitPath plus complete absence rounds use one pinned unique owner without
reconnect. Recheck original files/caller/Release after I/O and before observation.
No State, Source, processresource runtime, listener or mutable root is opened.
Absence grants no creation or readiness fact. The separate initial transition
repeats native admission before its own account, credential and generation births.

Enrollment alone supplies independently pinned initial provenance and the actual
mapped-executable check. Initial admission requires empty Release floors and a
fresh accepted first evaluation. Once any floors exist, use a candidate with
complete retained history; a new pin cannot restore initial provenance. The
second evaluation is fresh even when committing the first target made its
outcome no-update. Failure never refunds a committed root or floor.

Both evaluations use one frozen root/metadata/local/reference observation.
Release alone projects the three referenced metadata URLs from the fixed files,
including consistent-snapshot names; it authenticates the ordinary signatures,
rebuild policy, exact targets, expiry, root continuity and floors. The pair agrees
on Targets version/digest, platform/architecture/environment/Network, release
identity/version, source/input and common safety/qualification/protocol policy.
Per-target artifact/rebuild digests remain distinct. Program and descriptor
proof digests must match the actual frozen bytes, and the descriptor binds both
resources. `Check` requires the original snapshot caller, original Release owner
and unchanged complete floors. Copies of public bytes/Decisions cannot recreate
the private result; Close/cancellation cannot be bypassed with another caller.

The temporary Linux component consumer is `ardents-next infrastructure`: separate public
descriptor/inventory preparation and initial/candidate authentication. It reads
its actual executable through Enrollment, never an override or old backend.
Preparation owns finite original native input/output custody and signs nothing.
Signed metadata are explicitly supplied prerequisites, with controlled test
authorities only in independent fixtures. Unit bytes are an exact public release
resource; rendering and checking the fixed installed policy remain native
Installation responsibilities. No account, manager, staging, installation,
startup, Source listener or runtime history is opened by authentication. The optional preflight
consumer opens only read-only native observations. Release's own native
floors are the only durable authentication effects.

Canonical `ardents-node installation` directly composes Enrollment, Release and
these Source owners in its original root operation; `source start-installed`
directly consumes independent Startup before State/Source/Guard construction.
Canonical Control separately prepares public resources/inventory/serving inputs,
initial signed State and Source-specific Release metadata. No delegation to
Next, Endpoint authority or old runtime enters these accepting Source paths.

`source_install_linux.go` owns one finite initial stopped transition through
`install-initial-stopped`, directly consuming original initial provenance and
fresh Release checks. `source_account_linux.go` owns the fixed native helper,
database/auxiliary preimages, exact locked new identity and original helper join.
`source_birth_linux.go` retains the exclusive journal, original born descriptors,
finite exact effects, bytes/access and partial failures. These remain cohesive
private responsibilities in this existing package: only Installation admits
their phase/order and no generic mutation Interface is exported.
`source_binding_linux.go` owns the closed initial binding grammar shared by the
writer and the independent first-start reader. Canonical selected configuration
must match the exact Source request, template, rendered unit, account and target
identities. Parsing grants no initial provenance, Release or startup authority;
the first-start grammar refuses a predecessor rather than admitting replacement.
`source_selection_linux.go` independently retains the selected binding, exact
twelve-file sealed inventory, fixed unit, runtime credential files and original
directory descriptors. It rechecks original bytes, inode/access, complete inventory
and live clock writer/access policy, without freezing the clock inode or timestamp.
The initial stopped transition consumes this separate readback before returning;
neither file custody nor successful readback grants startup or State authority.
`source_directory_linux.go` owns the shared physical read-only directory opening
and original named/descriptor/access observation; its callers retain and close
their own descriptors. `source_history_linux.go` independently pins only the
original history directory and ancestors, checks its declaration against the
actual Release verifier and commits that identity with the binding in the private
initial journal. Release keeps all floor contents/policy and its separate lease.
The native history commitment grants no first-start authority and changes neither
the twelve-file inventory nor the immutable binding grammar.
`source_initial_records_linux.go` owns the complete canonical initial transcript
grammar, including exact phase/order, intended resources and matching born/ready
identities. `source_initial_linux.go` independently retains that root-only
transcript, selected Source resources and original Release history. The initial
stopped creator consumes this readback after its final record and returns its
writer lease only after its observers/helpers join. This reader grants no Start,
account or Release right; a future start separately admits the current principal
and fresh proofs. Account database records describe the initial helper's history,
not Source ownership of immutable host databases. State/participation contents
remain with their semantic owners.

`source_first_start_linux.go` retains fresh coherent proofs, complete original
initial readback, current principal and independent native observations under
its exclusive first-start journal. `source_start_storage_linux.go` and
`source_start_barrier_linux.go` retain original born journal/socket/guard custody,
peer/process checks and durable archival before the full completion ACK. An
uncertain attempt keeps its original process/cgroup until actual join; a full
ACK remains an irreversible handoff even if later reporting or Close fails.
`source_startup_linux.go` independently retains original selected inputs,
non-root invocation, process, cgroup, namespace, principal and manager through
the root-peer exchange and continuing checks. It shares no root lease or runtime
authority with the producer. Stop denies and interrupts before physical Close
joins original observers; command composition joins State users before retiring
Startup and erasing loaded keys. Read-only namespace/runtime identity and native
physical adapters preserve their own purposes and failure/Close lifetimes.
No restart, replacement, replay or recovery continuation is admitted here.
`source_loaded_linux.go` owns Source's complete loaded stopped-policy comparison;
the separate systemd SourceStopped handle owns physical connection/cancellation,
one explicit reload and detached complete typed observations. It grants no Start.
Input/destination ancestors remain original across reload. Manager generator
output directories have separate fresh phase observations after the owned reload,
while read-only preflight retains all of its original namespace pins.

The initial journal, twelve-file sealed generation, exact selected binding and
fixed unit are defined in the [technical owner](../../../../docs/technical/network-route-node.md#initial-stopped-source-persistence).
Semantic State/participation directories remain empty. No failure removes a
prefix, adopts foreign resources, resets floors, retries an uncertain birth or
implements continuation. Account/helper and native manager observations do not
constitute independent distribution trust or qualify an operational installation.

Current reference/technical/testing owners describe formats and checks. This
component neither establishes first-distribution trust before execution nor
accepts a bootstrap receipt or qualifies an installed Source, complete operator
cutover or system. Other five invocations have no accepting path.
Before any installed Source execution the completed exact public bootstrap
receipt requires direct Product Owner acceptance. Its presence, a Start job or
ACK supplies neither that human decision nor State authority or runtime readiness.
